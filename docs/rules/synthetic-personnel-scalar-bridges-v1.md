# Neutral personnel scalar proposals: helper proof versus owner integration

`internal/synthetic-personnel-scalar-bridges.ts` adds two pure internal helpers. No persistent world, assignment owner, target-city balance or RNG journal is created. No real person/ownership/appointment writer, capture, diplomacy, P078 or Closing path is called. Outer world must bind fixed synthetic facts, derive every current value from its unique history, enforce role/reservation/action gates, and atomically commit the returned patches. Source services were actually read; code was not executed or typechecked.

## projectSyntheticOfficeVacancies

Exact input `{ownerId,rulerId,titleKey,officers,mode}`. 1..8 existing same-owner synthetic officers each have `{id,personId,ownerId,role,eligible,merit,trueLoyalty,selectorStats,salary,officeId}`. Fixed personId mapping is unique0..65535; it is a synthetic selector key, not a native person index. `selectorStats={leadership,war,intelligence,politics}` each1..100, merit0..60000, positive trueLoyalty<=255, salary0..1000000, officeId null or0..79. `eligible` must derive from actual resident/unacted/unreserved eligibility, never a caller permission declaration. `mode` weighted-threshold or role-affinity is fixed scenario policy or an authorized typed choice.

Actual createOfficeAssignmentState → planOfficeAssignments → applyOfficeAssignmentPlan is invoked with fill-vacancies-v1 only. Title/tier/merit/loyalty and scoring/tie order remain the real service's checks, including its explicit provisional qualification boundary. Existing assignments remain, no dismissal/rebuild. For **newly assigned** officers, actual resolveFinancePayroll resolves named-office catalog monthly salary. Output patches contain officeId and salary together. Unassigned/retained officers keep current salary; no unassigned salary or demotion formula is invented. Atomic owner adoption must update its one office metadata and salary field together before subsequent monthly settlement. Assignment itself does not deduct a monthly salary, modify loyalty/merit, or create another payroll balance.

Catalog bonusText is descriptive only. No numeric AP/gold/production discount is inferred or applied (`discountApplied:false`). Salary catalogs and qualification source existence do not prove native office writers or unimplemented bonuses. The integrated office owner commits the one current salary field but makes no guarantee of future affordability or fund reservation. Existing real monthly shortfall/positive-loyalty atomic rejection remains in force; the pure helper alone cannot prove that owner integration.

## projectSyntheticRumorScalar

Exact input `{scenario,rngDrawOffset,commandId,actorId}`. `scenario` has exactly `{date,attackingForce,targetForce,originCity,targetCity,actors,targetOfficers,relations,rng}` using the actual rumor-scalar DTOs. All actor/force/city/defense/ruler IDs must be synthetic and globally distinct; origin and target owners/cities differ. Actors1..8; target officers1..8 with positive trueLoyalty. Governor/ruler/strategist are fixed distinct target facts. It must be a separately declared target-city scalar owner, **not the current city relabeled enemy**. Current actor intelligence/usedThisTurn, origin gold/AP, target security/loyalty and the current RNG state must be derived by the enclosing owner.

Helper supplies the registered policy, hostile relation, scope and one-turn projection horizon; it calls createRumorScalarStateV1 then actual AttemptRumorScalar. The old kernel pays gold200/AP30 on probability success or failure, uses actual actor usedThisTurn eligibility, synthetic probability and target selection, and no original capture/diplomacy/XP/travel/ownership finalizers. Any target loyalty reaching0 is additionally rejected atomically in this adapter. No successful patch is returned on rejection.

Crucially scenario.rng.seed means the **current outer nonzero xorshift state**, not the original initial seed. `rngDrawOffset` is the current cumulative raw-draw count, bounded1000000. Output carries the new RNG state and cumulative count, and global-indexed draws; the complete old receipt retains local projection indices and local turn0 explicitly. This is mechanical continuation of the same RNG stream, not re-randomizing each attempt. Current usedThisTurn flags preserve actor use despite local projection turn0. Outer actual date/turn and full command IDs remain authoritative. No AdvanceRumorTurn is exposed; no resource refresh or extra world clock is created.

Output originPatch updates gold/AP and actor acted=true; targetPatch updates only the fixed target security and same-ID target loyalties; RNG updates commit in that same transaction. Owner must reject duplicate/stale commands, preserve all receipts/inputs, and discard all patches if a sibling action fails. There is no local salary/diplomacy/bandit consequence even if target security reaches0; this is explicitly scalar-only. True loyalty remains one value, never a duplicate displayed-loyalty account.

## Ruler binding correction
Office input requires `rulerId` distinct from `ownerId`, derived by the owner from its actual synthetic force. Every officer requires `role: ruler|ordinary-officer`; exactly the matching rulerId is permitted ruler role and cannot be relabeled ordinary. The actual source receives that role, preserving ruler exclusion and rejecting a ruler holding a named office. The roster need not include the ruler, but the caller cannot override its ID through a public action. Previous blanket ordinary-officer projection is withdrawn.
