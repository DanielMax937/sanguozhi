# E12 技巧研究完成功绩

更新：2026-09-30。主目标版本：PC-PK1.1。

## 1. 本轮结论

技巧研究完成后的功绩存在两套长期流传、彼此冲突的表：

| 等级 | 现行日文 Wiki《功绩值》 | 日文 Wiki《小ネタ》/2006 中文攻略 |
|---:|---:|---:|
| Lv1 | 500 | 500 |
| Lv2 | 1000 | 1000 |
| Lv3 | 2000 | 1500 |
| Lv4 | 3000 | 2500 |

因此当前能锁定的是：

- Lv1 = 500、Lv2 = 1000：两套资料一致；
- Lv3 / Lv4：存在 2000/3000 与 1500/2500 的真实资料冲突；
- **尚未恢复 PC-PK1.1 的研究完成 caller / 功绩常量，不能把任一套写成 reverse-engineered exact。**

项目此前使用的：

```text
500 / 1000 / 2000 / 3000
```

暂时继续作为主目标的兼容候选值，但证据等级改为：

```text
documented-current-wiki-candidate
```

而不是“主表高置信”或“PC源码已确认”。

## 2. 外部资料冲突

### 2.1 现行日文 Wiki 功绩总表

《功績値》当前表写：

```text
技巧研究：
Lv1 500
Lv2 1000
Lv3 2000
Lv4 3000
```

来源：

- https://w.atwiki.jp/sangokushi11/pages/113.html

该页没有为这四个数值标注 PC/PS2/Wii、无印/PK 或补丁号，所以它只能证明“现行 Wiki 主表采用这组值”，不能单独证明 PC-PK1.1 原 EXE 就是这组常量。

### 2.2 同一 Wiki 的“小ネタ”

同站《小ネタ》的功绩刷法仍写：

```text
Lv1 500
Lv2 1000
Lv3 1500
Lv4 2500
```

来源：

- https://w.atwiki.jp/sangokushi11/pages/15.html

这说明冲突不是单纯的中日资料翻译误差；同一社区资料库内部也保留两套表。

### 2.3 2006 中文攻略

2006-04-27 的游民星空《快速长功绩的方法》同样写：

```text
一级 500
二级 1000
三级 1500
四级 2500
```

来源：

- https://www.gamersky.com/handbook/200604/22600.shtml

这是明确的早期资料锚点。它可以作为早期无印时期的文献证据，但不能据此反推“所有无印补丁都永远是这套值”，更不能反推“PK一定改成2000/3000”。

## 3. PC-PK1.1 逆向资料能证明什么

311MemoryResearch / sergi 的繁中 PK1.1 逆向资料已经能证明大量相邻规则：

- `005D7ED7`：人才府使技巧研究时间 -20 日；
- `005D7EF0 / 005D7EF4`：最低 1 旬；
- 技术研究能力经验：
  ```text
  消费技巧P / 100
  ```
- 同一“经验、功绩与技巧点”章节给出了训练、巡查、流言、单挑等大量**明确功绩地址与常量**。

但是公开文本里没有出现“技巧研究完成 +500/+1000/+xxxx”的对应地址。

另一个逆向研究记录能定位：

```text
研究技巧：005D8F68
```

但没有继续展开到研究完成后的功绩写入 caller；研究目录备忘中“研究技巧”也没有像已完成项目那样标记 `OK`。

因此 E12 的源码结论是：

> PC 研究动作能够定位，但公开逆向资料尚不足以恢复“研究完成 -> 每名武将功绩”的精确常量链。

这不是对某一组数值的反证，只是明确说明目前缺的是哪一段证据。

## 4. 不能偷推一个“功绩 = 技巧P / 2”公式

旧表：

```text
技巧P：1000 / 2000 / 3000 / 5000
功绩： 500 / 1000 / 1500 / 2500
```

确实恰好满足：

```text
功绩 = 技巧P / 2
```

但目前没有找到 PC 指令或官方说明证明游戏实际按这个公式动态计算。

所以这个关系只保存为“旧表的算术特征”，**不能作为原作算法**。尤其现行 2000/3000 表本身就不满足该关系。

## 5. 版本边界

当前最安全的版本表达是：

```text
early-2006-guide:
  500 / 1000 / 1500 / 2500

current-wiki-main-table:
  500 / 1000 / 2000 / 3000

PC-PK1.1-exact:
  unresolved
```

禁止直接写成：

```text
Vanilla = 500/1000/1500/2500
PK      = 500/1000/2000/3000
```

因为目前没有找到“PK改了Lv3/Lv4功绩”的补丁说明或二进制对照。

所以 E8 的版本差异表暂不新增这条 transition。

## 6. 执行武将分配语义

旧社区资料常把技巧研究描述成给执行武将刷功绩，另有玩家整理写作“全”，但尚未恢复 PC 完成 caller 来确认：

- 1～3名参加者是否每人都获得全额；
- 是否存在主执行者/副执行者差异；
- 中途人员状态变化时如何结算。

因此“每名参与武将均获得表中全额”目前仍应标为攻略/经验层，而非源码层。

## 7. 引擎实现策略

### fidelity / 严格复刻

如果目标是“原 EXE 精确复刻”，则 Lv3/Lv4 必须保持：

```text
unresolved
```

直到找到：

- PC-PK1.1 完成研究的功绩调用地址；
- 或同一版本可重复的存档/内存实验。

### 当前兼容候选

为了不破坏项目现有行为，可以继续：

```text
[500, 1000, 2000, 3000]
```

但必须同时携带：

```text
evidence = documented-current-wiki-candidate
exactness = unresolved
conflict = [500,1000,1500,2500]
```

结构化证据见 `docs/sources/technique-research-merit.json`。

## 8. 仍 open

1. PC-PK1.1 完成研究 -> 功绩写入的 exact caller / 常量；
2. 500/1000/1500/2500 与 500/1000/2000/3000 的真正版本/平台映射；
3. 1～3名参与武将的逐人功绩分配；
4. Vanilla 各补丁、PS2/Wii 的等价性；
5. 若存在版本改值，精确 transition patch。
