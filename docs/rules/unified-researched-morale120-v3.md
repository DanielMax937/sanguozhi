# Technique16's actual 120-morale domain across one owner

This candidate depends on the fixed T03/T33/FHG owner chain, not a claim those local candidates have already merged. Optional `energyConfig:{profile:'researched-morale120-v1'}` enables one finite compatibility domain across the existing city/resource/field owner. Old absent-profile defaults and independent v1 services remain unchanged.

## Source and qualification

The actual Train ruleset and calculation/state validators already distinguish normal morale cap100 and learned technique16 cap120. Learning the technique does not itself award morale. This change does not invent a new energy pool or turn the intensity value into a conserved resource. It removes inconsistent100-only adapters only behind the explicit profile and actual replayed technique qualification.

The new owner requires progress, PK and the existing research capability. Immutable city genesis retains moraleCap100 and initial city/cargo values must satisfy100. Private research extension derives currentMoraleCap as100 or120 from the sole current completed-technique list. Current city validation and domestic/recruitment projections read that derived cap; saved original genesis, jobs, fees and start snapshots are not overwritten or rebased. Before research16, no high-cap recruitment/transfer path is available. On completion, only the admissible upper bound changes; current morale and all resources stay as the real completion/reward kernels specify.

## Actual consumers and atomic transitions

Train uses the new opt-in bridge over the same real executeCommand Train kernel and its full resource/progress/reward patch. It passes the existing training-supported technique16 fact and rejects unsupported rules rather than manufacturing a fake base attribute. City current morale, AP, TP, used-turn and WAR XP remain the same owners.

City↔transport transfer uses the new named120 validator/proposal functions with the actual full completed-technique list and matching home ownerId. The underlying capacity planner still checks all fifteen coordinates, positive troop counts, receiver capacities, source availability and weighted-floor morale. Type5 reserved stock cannot be spent and still occupies capacity. It is a temporary current-account proposal, not a new120 independent save or a second persistent ledger. Empty cargo lists still validate the positive city/cap contract.

Deploy inherits current city morale into the same field energy value; it does not subtract a conserved energy reserve. Return credits actual positive troops and uses the existing troop-weighted floor mixture of current city morale and actual remaining field energy. It does not restore initial energy or erase costs. A profile-qualified value101..120 remains usable through the full field movement/fire/status/recovery/combat adapter chain; unsupported values reject atomically, never clamp.

## Field history and owner facts

Field creator receives an explicit energy profile with the home owner and its initial actual technique list (currently empty in this research genesis), plus fixed enemy technique facts when an enemy exists. Each private OuterStep receives the actual ending home technique list from the same replayed research owner. The field action uses the preceding step's current list and cap, then synchronizes the completed list; thus a Tick that completes16 does not retroactively rewrite earlier fire/action semantics. No energy amount is credited by synchronization. Non-profile public commands cannot supply this metadata or bypass the outer owner.

Enemy and home qualifications are distinct. Enemy facts are independent immutable encounter facts; home research never upgrades enemy cap. Actual combat receives the same complete lists and actual derived energyCap. It does not erase other learned techniques to pass an unsupported gate. The explicit food-raid profile, request and atomic G settlement remain mandatory for the applicable actual attack; energy compatibility does not relax them.

## Replay and exclusions

Original outer commands regenerate every cap, account and private field step. No caller-supplied cap token, arbitrary delta or modified derived city save is trusted. The old bounded-city standalone loader is not presented as accepting an owner-extended current state; only the full versioned owner root proves its additional transitions. Existing completion-tail reservations, history/node/byte limits and dates remain in force. Any failed sibling phase or unsupported domain rejects the entire event including costs, action marks and RNG.

This supports the known technique16 morale rule, not unlimited255 morale, new troop finalizers, starvation injury, real ownership, P078 or Closing. Static inspection only; no candidate, tests, typecheck or build execution.
