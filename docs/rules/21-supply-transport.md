# E6 补给与输送

更新：2026-09-30。主目标版本：PC-PK1.1；PC/CS 交互差异单独标注。

## 1. 先区分两个动作

三国志11的“输送”至少有两条不同的完成路径，不能混为一个函数：

1. **输送队到达城市 / 港 / 关**：把运输资源送进据点并完成输送。
2. **输送队给野外己方战斗部队补给**：在地图上把兵、金、粮及相关兵装转给目标部队。

二者的功绩值不同：

```text
输送到达据点：+200 功绩
野外补给：    +100 功绩
```

PC-PK1.1 地址资料已经直接锁定：

```text
004BF522  输送队抵达据点，功绩 +200
```

“补给+100”由日文Wiki功绩表与长期实测确认；目前尚未定位同等级的PC逐指令地址。

## 2. 输送队本身的容量

沿用 E1 已确认的 `TroopType=1`：

| 资源 | 输送队上限 |
|---|---:|
| 武将 | 1主将 + 最多2副将 |
| 兵力 | 60,000 |
| 金 | 100,000 |
| 粮 | 500,000 |

运输中的枪、戟、弩、马、攻具、舰船都保存在部队12组 `EquipmentStatus` 中；它们是货物，不会把输送队改成战斗部队。

兵装逐类型上限相关地址已经定位：

```text
出阵时：          006157C1 / 006157D8
运行时：          004962CF / 004962D6
补给之后重新封顶：00496306 / 0D / 28 / 2F
```

但当前公开逆向文本只留下地址，没有把“不同兵装ID对应的具体上限值”展开出来。因此本轮**不伪造逐类型兵装容量**。

## 3. 野外补给的可补资源

PC/CS长期实机资料确认，输送队可以向己方出阵部队补给：

- 兵；
- 金；
- 粮；
- 与补兵对应的数量型兵装。

对枪 / 戟 / 弩 / 马部队：

```text
补入 N 名士兵
=> 输送队还必须能同时提供 N 件当前兵科对应兵装
```

例如目标是枪兵：

```text
目标缺3000兵
输送队有3000兵但只有2000枪
=> 最多只能补2000名枪兵
```

这与 E1 已恢复的原出征逻辑一致：兵装ID1～4属于“兵数=兵装数量”的数量型装备。

剑兵不需要一一对应的剑库存。

对冲车 / 井栏 / 投石 / 木兽 / 楼船 / 斗舰，不把“补兵”误实现成每个士兵消耗一件攻具或舰船；这些仍是部队级件数装备。

## 4. 目标部队的兵力与资源上限仍然生效

补给不会绕过目标部队自己的容量函数：

```text
004957B0 GetTroopStrengthLimit
004957F0 GetTroopMoneyLimit
00495810 GetTroopFoodLimit
```

普通战斗部队已有：

```text
金上限 10,000
粮上限 50,000
兵力上限 = 主将指挥上限（含军制改革等）
```

所以参考实现必须先计算目标剩余容量：

```ts
addTroops <= targetStrengthLimit - targetStrength
addMoney  <= targetMoneyLimit    - targetMoney
addFood   <= targetFoodLimit     - targetFood
```

枪戟弩马再加：

```ts
addTroops <= supplierMatchingEquipment
```

但**最终补给caller本身尚未完整逆向**，因此资源写入的逐字段顺序、超限部分究竟如何返还/保留，以及多资源同时补给的事务顺序继续标 open。

## 5. 补兵后气力按兵数加权

日文Wiki有明确可复现实测：

```text
目标部队：
  2500兵，气力0

补到：
  5000兵

新补士兵气力：
  100

结果：
  5000兵，气力50
```

核心语义就是：

```text
新气力 =
(旧兵数×旧气力 + 新增兵数×新增兵气力)
/
(旧兵数+新增兵数)
```

项目中另有源码 helper：

```text
004B9840 GetBuildingCombinedStrength
```

它明确以：

- 据点原兵力/气力；
- 新增兵兵力/气力；

来计算合并后的据点气力。

这说明“新旧士兵按人数混合气力”也是原程序中的通用数据模型，而不是只存在于攻略文字里。

不过目前尚未取得**野外部队补给**调用该 helper 或等价 helper 的逐指令文本，因此：

- 加权平均核心语义：confirmed/high；
- 小数时最终整数取整模式：open。

## 6. PC版：手动补给与自动补给是两种入口

PC版资料明确：

### 6.1 手动补给

把输送队移动到目标部队相邻位置，再选择“补给”：

```text
=> 出现补给量滑块
=> 玩家可自行选择补给量
```

这也是 Wiki 所说：

> PC版では補給量の任意調節が可能

因此 PC 引擎 UI 层不能照搬主机版固定补给量。

### 6.2 自动补给

如果直接把目标己方部队作为输送队的移动目标：

```text
=> 到达后自动补给
=> 会向目标的最大兵数 / 最大物资方向补
```

这也是长期 PC 实机行为。

自动补给和手动补给最终应共享同一容量/合法性规则，但具体 finalizer 是否完全同函数仍未恢复。

## 7. CS / 主机版是另一套补给交互

CS版不能像 PC 一样自由指定补给量。

长期实测的固定规则为：

```text
兵：最多3000
金：最多1000
粮：通常按补入兵数处理，并会考虑给输送队保留行军口粮
```

如果输送队没有足够士兵/对应兵装/金，则按能提供的实际量补。

这些数字只标：

```text
[CS][empirical-high]
```

**绝不能拿来覆盖 PC-PK1.1。**

## 8. 补给行为的功绩与经验

### 8.1 输送队到达据点

```text
功绩 +200
```

PC-PK1.1 地址：

```text
004BF522
```

日文 Wiki 功绩表也独立给出“輸送 到着 200”。

### 8.2 给野外部队补给

```text
功绩 +100
统率经验 +2
```

日文 Wiki 的经验表明确写：

```text
輸送部隊を率いての補給 -> 統率経験 +2
```

并有 PC 版手动补给同样获得 +2 的实测记录。

当前证据支持的是**负责率领输送部队执行补给的武将**获得该统率经验；不要擅自扩大成“输送队三名武将全部各+2”。

“到达据点+200”与“野外补给+100/+2统率”也不能合并成一次动作同时获得两套奖励。

## 9. 输送到据点与容量

据点资源都有自己的 getter / limit / setter：

```text
GetSPTroopStrength / GetSPTroopStrengthLimit
GetSPMoney         / GetSPMoneyLimit
GetSPFood          / GetSPFoodLimit
GetSPEquipment     / GetSPEquipmentLimit

SetSPTroopStrength
SetSPMoney
SetSPFood
SetSPEquipment
```

以及统一增减 helper：

```text
004AE3C0 AdjustSPSoldier
004AE430 AdjustSPEquipment
004AE2A0 IncreaseSPMoney
004AE300 AdjustSPFood
```

这证明到达据点的资源必须进入据点各自上限模型。

但本轮仍没有找到“输送到达据点”完整 finalizer 的逐字段调用链，因此暂时不能写死：

- 先加兵还是先加粮；
- 超上限资源是丢弃、留在输送队、还是有其他 UI 处理；
- 攻具/舰船超上限时的具体处理顺序。

这些继续留 open。

## 10. 输送队不能被另一输送队补给

日文 Wiki 长期实测明确：

```text
補給隊に補給は出来ない
```

因此通用目标资格中应把：

```text
target.TroopType == TRANSPORT
```

排除在普通“输送队→战斗部队补给”之外。

当前还没有恢复该 target-type hard gate 的 PC 指令地址，所以证据等级保留为 `empirical-high`。

## 11. 输送队损失时的货物

日文 Wiki 实测记录：

- 输送队因粮尽或栈道等环境损耗而消灭：所载物资消失；
- 被敌军攻击击破：货物可能被敌方掠夺。

这是重要 gameplay 边界，但目前没有恢复对应 loot finalizer 的 PC 原函数，因此继续标 `empirical-high`，不把具体掠夺比例写成公式。

## 12. 行动力与军事府边界

PC-PK1.1 已定位：

```text
005DB840 GetExpeditionActionPointCost
005DB107 军事府使“输送”行动力减半
005DB86E 军事府使“出征”行动力减半
```

说明“出征”和“输送”虽共用一部分界面/入口，但在军事府判断中有独立地址。

本轮没有恢复 `005DB840` 的完整原函数体，因此这里只确认：

```text
PK城市有军事府 -> 输送AP减半
```

不在 E6 重新伪造未核对的基础 AP 常量。

## 13. E6 当前结论

已经锁定或高置信确认：

- 输送到据点和野外补给是两个独立动作；
- 输送到据点功绩+200，且有PC地址级证据；
- 野外补给功绩+100、率领者统率经验+2；
- PC可手动调节补给量；CS不可；
- PC另有以目标部队为移动目标的自动最大补给路径；
- 补兵受目标兵力上限约束；
- 枪/戟/弩/马补兵必须同时有等量匹配兵装；
- 补兵后气力按新旧兵数加权平均；
- 输送队不能成为普通补给目标（empirical-high）；
- 输送到据点必须服从据点资源上限体系；
- 军事府让输送AP减半；
- 木牛流马/搬运/操舵移动效果沿用 B4，不在本节重复改写。

仍 open：

1. PC-PK1.1 野外补给完整 finalizer；
2. 输送抵达据点完整 finalizer 与资源写入顺序；
3. 输送队12类兵装的逐类型容量；
4. 补兵气力加权平均的小数取整模式；
5. 自动补给的逐资源优先级；
6. 据点/部队超上限时剩余货物的精确处理；
7. 输送队不能补给输送队的PC硬分支地址；
8. 输送队被击破时货物掠夺的原函数与精确比例；
9. `005DB840` 原始基础AP完整函数；
10. Vanilla/主机版除已标出的UI差异外是否还有内部差异。
