# E5 兵粮消耗

更新：2026-09-30。主目标版本：PC-PK1.1。

## 1. 旬级调度

原函数：

```text
0059BF40 每旬城市港关和部队耗粮
```

每旬顺序至少包含：

1. 遍历87个城市/港/关；
2. 对有粮据点计算并扣除驻屯耗粮；
3. 遍历地图部队；
4. 对有粮部队计算并扣除部队耗粮；
5. 若本旬扣粮后恰好变成0，则加入提示/消息列表。

如果进入本旬时兵粮已经是0，`0059BF40` 会直接跳过“计算并扣粮”函数；粮尽导致的后续逃兵不在 `0049D200/0049D2E0` 里完成。

## 2. 城市 / 港 / 关驻屯耗粮

原函数：

```text
0049D200 计算城市港关兵粮支出
```

未着火时：

```text
raw = garrisonTroops × 0.025
```

即常见整数语义：

```text
驻屯基础耗粮 ≈ 兵力 / 40 / 旬
```

结果通过 `00707A74 ConvertFloatToInteger` 整数化；若兵力>0而结果<=0，强制最低耗粮1。

因此“驻屯 /40”现在是 PC-PK1.1 原函数确认，不再只是 Wiki 经验值。

## 3. 港 / 关 + 屯田：直接0耗粮

`0059BFBA～0059BFD9` 只对设施类型1/2，即港、关，检查特技：

```text
0x4E = 屯田
```

如果港/关内存在有效屯田武将，旬级 caller **直接跳过整个耗粮函数**。

所以：

```text
港 / 关 + 屯田
=> 驻屯耗粮 = 0
```

城市不走这条屯田免粮分支。

## 4. 野外战斗部队基础耗粮

原函数：

```text
0049D2E0 计算部队兵粮支出
```

战斗部队先根据同势力防御设施确定一个耗粮倍率，再统一乘：

```text
troopStrength × multiplier × 0.05
```

### 4.1 无防御设施

```text
multiplier = 2.0
=> 兵力 × 0.10
=> 兵力 / 10
```

所以：

```text
普通野外战斗部队 = 兵力 / 10 / 旬
```

### 4.2 阵 / 砦 / 城塞

PC-PK1.1 原浮点常量：

| 环境 | 源码 multiplier | 相对无设施 | 10000兵参考耗粮* |
|---|---:|---:|---:|
| 无 | 2 | 100% | 1000 |
| 阵 | ≈5/3 | ≈83.33% | 833 |
| 砦 | ≈4/3 | ≈66.67% | 666 |
| 城塞 | 1 | 50% | 500 |

`*P0-10 已确认 `00707A74` 为 MSVC `_ftol2`；这些正耗粮 raw 的末端 floor 为 PC-PK1.1 exact。`

因此源码更接近：

```text
阵：约减 1/6 = 16.67%
砦：约减 1/3 = 33.33%
城塞：减 1/2 = 50%
```

日文 Wiki 长期写作 15% / 30% / 50%，前两项应视为界面/攻略层近似，fidelity 实现应优先使用 EXE 常量。

### 4.3 重叠防御设施

本函数调用：

```text
0049D180 获取与部队相同势力的防御系列设施类型ID
```

当前公开文本没有展开 `0049D180` 的完整选择逻辑。因此当部队同时处在多个不同级别防御设施范围内时，“到底取最高级、最近或其他优先级”继续保留 open；不要自行相乘叠加。

## 5. 输送队：兵力 / 20，且不吃阵砦城塞减粮

`TroopType=1` 时源码直接：

```text
multiplier = 1.0
```

并跳过防御设施判断。

所以：

```text
输送队耗粮
= 兵力 × 1.0 × 0.05
= 兵力 / 20 / 旬
```

而且：

```text
运输队在阵/砦/城塞范围内
=> 不获得上述减粮倍率
```

这比简单写“运输队是普通部队一半”更精确。

## 6. 着火会额外烧兵粮

### 6.1 野外部队

若部队着火，`0049D2E0` 额外计算：

```text
fireFood =
  currentFood
  × (6 - troopPolitics × 0.05)
  × 0.01
```

其中 `troopPolitics` 是 E2 已合成的部队政治。

正常政治0～100时：

```text
政治0   => 当前存粮 × 6%
政治100 => 当前存粮 × 1%
```

最终旬耗粮：

```text
normalTroopConsumption + fireFood
```

运输队同样会进入这个着火附加耗粮分支。

### 6.2 城市 / 港 / 关

着火据点公式完全同构，但使用太守政治：

```text
fireFood =
  currentFood
  × (6 - prefectPolitics × 0.05)
  × 0.01
```

无太守按政治0处理，即当前存粮额外约6%。

然后再加驻屯兵力的 `兵力×0.025`。

## 7. 整数化与最低1

据点和部队两个支出函数最终都调用：

```text
00707A74 ConvertFloatToInteger
```

若：

```text
兵力 > 0
且整数化结果 <= 0
```

则支出强制为1。

P0-10 已确认 `00707A74` 是 MSVC `_ftol2`，语义为向0截断。耗粮 raw 在正常规则域为正，因此这里可以直接写成语言级 `floor`。仍需单独保留的是防御设施浮点常量 bit pattern 与 x87 中间精度，而不是最终转换方式。

## 8. 粮尽与逃兵：当前证据边界

旬级扣粮函数确认：

- 有粮时才执行扣粮；
- 本旬扣到0时记录“粮尽”对象用于消息；
- 本函数本身**没有修改部队兵力**。

日文 Wiki 只明确说粮食为0后兵力会每旬大幅下降。现有项目曾采用：

```text
A × 0.76^N
```

作为经验拟合，即每粮尽旬保留约76%。

本轮没有在 PC-PK1.1 逆向资料中找到这条逃兵闭式对应的原函数，因此：

```text
粮尽逃兵 ≈ 每旬保留76%
```

继续标为 `empirical-high / fallback`，不能升级为 reverse-engineered。

同时要与：

```text
00599AA0 兵临城下逃兵
```

严格区分。后者是敌部队靠近城市/港关造成的另一套据点逃兵机制，与“粮尽”不是同一函数。

## 9. 旧规则的纠错

现在确认：

- “战斗部队 /10”——正确，升级为源码确认；
- “输送队 /20”——正确，升级为源码确认；
- “据点驻屯 /40”——正确，升级为源码确认；
- “港关+屯田=0”——正确，且仅港/关适用；
- “阵/砦/城塞减粮15%/30%/50%”——前两项不是 fidelity 精确值，应改为源码常量对应约16.67%/33.33%/50%；
- “运输队在防御设施范围也减粮”——错误，源码直接跳过该分支；
- “着火只掉兵，不额外烧粮”——错误，部队与据点都有政治相关的额外存粮损失；
- “粮尽0.76已经源码确认”——错误，目前仍只是实测层。

## 11. 仍 open

1. `0049D180` 在多个不同防御设施范围重叠时的选择优先级。
2. 防御设施浮点常量的 bit-exact 值与 x87 中间精度极端边界；最终 `00707A74` 转换已闭合。
3. 粮尽导致部队/据点逃兵的 PC-PK1.1 原函数及闭式；当前约76%保留率仍为实测层。
4. Vanilla / 主机版防御设施减粮浮点常量是否完全相同。
5. 着火额外耗粮在异常超100政治/修改器环境中的边界不纳入原版规则。
