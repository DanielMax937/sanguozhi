# Synthetic owner technique research leaves

Pure private helper, not yet a public unified command. Base evidence: `packages/engine/src/technique-research-lifecycle.ts` at main f132870bb58505acd0572c23e3ba91592eefa849, archived by the command-contract task. This implementation copies the existing nextDate/debit/credit/timing/complete calculations unchanged, while start and current-owner validation adapt existing semantics. Old service defaults/files are untouched. No tests, build, typecheck or candidate execution performed.

## Contract

`planSyntheticTechniqueStart(context,{jobId,techniqueId,officerIds})` and `advanceSyntheticTechnique(context,job)` return `{ok,job,patch,receipt}`. Job wrapper `{source,lastTurn}` retains the old source job's startSnapshot/timing/fees/completion with the SAME `job:synthetic-*` identifier used in the shared reservation ledger. No temporary standalone state, alias lock or second resource owner exists.

Exported SyntheticTechniqueContext is exact: cityId/forceId/corpsId; turn/date; gold/AP (`actionPoints`)/TP (`techniquePoints`); completedTechniqueIds; remainingTickCapacity; enemyWithinTwoCells; talentOffice; difficulty; officers; activeResearchJobId; policies. Officer fields: id/forceId/cityId/available/role/effectiveAttributes/skillKeys/xp/merit/actedTurn/reservationJobId. effectiveAttributes and xp each contain leadership/war/intelligence/politics. `skillKeys` may contain only evidenced guidance, not guessed mappings from unrelated numeric skills. Policies must equal a combination already registered by the old technique service; no external callback or formula accepted.

Caller constructs context from one owner ledger and current role/locks; action data never supplies balances, difficulty, abilities, skills or enemy state. One force research job at once, 1..3 distinct current resident actors. All prior technique prerequisites must exist. Exact gold/TP from catalog, AP50 and participating guidance half-gold/nonstacking. Timing preserves old guide-family policy or explicitly selected inferred70-point bands and complete talent-office reduction. No claim of native timing matrix. Fees, attributes, effective policies and due date are snapshotted. Actor locks and acted markers set atomically with debit and job.

Advance receives the already advanced owner turn/date, requires lastTurn+1 and full matching expected xun date. It reconstructs the original start job from its snapshot, compares complete timing/fee/work metadata and current policies, checks current same-person reservations/resident availability and progresses exactly once. No AP recovery or calendar mutation is performed; nextDate is used only to verify/project due dates. At completion the old kernel unlocks technique, credits selected actors' related XP and merit under old caps/policies, releases reservations and sets completion-turn acted. An accepted completed job is a permanent history record, not startable again.

Patch is finite: gold/AP/TP, completedTechniqueIds, activeResearchJobId, and selected `{id,xp,merit,actedTurn,reservationJobId}`. Receipt contains actual timing/fees or remaining counts/completion reward details. No arbitrary public delta interface. Source job validation is not authorization by itself: outer genesis+full accepted-command replay must reconstruct the original accepted start and all intervening actions; caller-provided job snapshots must not bypass owner replay.

## Required owner integration

- Reuse the same typed reservation extension as forge and production; do not hide locks or clear them temporarily. Research actor deployment, city actions and other job starts must see these reservations. Job histories and unlocks are authoritative exactly once.
- TP and gold/AP are current shared balances; `xp.war` is the SAME cumulative progress WAR XP. Old technique service keeps effective attributes stable despite XP, whereas unified training progress derives WAR from cumulative XP. If owner derives WAR after this completion, name that cross-service integration policy explicitly; do not create parallel XP or silently pretend old standalone semantics are unchanged. Validate shared XP/growth limits before commit; incompatible output rejects the entire tick.
- The existing Train bridge's domain100 rejects technique16. If research unlocks16, next Train must reject explicitly until a compatible higher-cap profile exists; do not drop unlock16 from projection to force acceptance. Other technique unlocks do not imply their combat/passive effects are implemented.
- One WorldTick controls AP/date/natural events, production, forge, research and field progression. Each helper runs on a detached candidate. Any later budget/invariant/resource/field failure discards all phases. Released research actors remain acted in completion turn.
- Start requires enough remaining completion boundaries; owner derives remainingTickCapacity from finite outer horizon and reserves future accepted-history slots. Extending finite horizon for PK research up to18旬 is ordinary implementation scope, not permission-restricted work. This helper itself does not raise an owner limit.

Scope excludes P078, Closing, real-person allegiance/casualties, zero terminal processing and whole-season health. Ordinary synthetic research rewards are allowed. Native global scheduler/effects remain unimplemented unless separately connected and evidenced.

`validateSyntheticTechniqueContext(raw)` performs detached pure context/config validation for owner genesis, returning only `{ok}` or a reason. It creates no state, fakes no start and ignores no resource failure.
