# 训练内核运行规则与旬推进政策

对应PR #4/#5，当前profile为 `pk-training-lifecycle-v2`。这是单势力/第一军团的合成训练域；不是完整游戏调度器。源内训练资格、累计经验与重置证据见[82](82-training-lifecycle-source-profile.md)，算术证据见[19](19-training-morale.md)和[46](46-training-morale-exactness.md)，接口/迁移见[生命周期工程文档](../engine/pk-training-lifecycle.md)。下列支持域和调度选择明确属于工程适配，clean-stock等价性仍未认证。

## 1. 资格与训练提交

据点须属当前势力和军团，有兵、本旬未训练、当前气力低于上限。选1–3名不同己方武将，驻地与目标一致，身份0–3、位置为据点、无任务且未行动；AP和状态/profile合法。所属、同地、去重等强约束不能全部归给原参数helper。身份、位置和任务是独立维度：俘虏身份5，在外/部队属于位置，无额外虚构的“出征身份”。

默认不允许满气力刷经验，也不为持续演示自动扣气力。替换资格gate不得绕过所有权、同地、行动、身份/任务、AP及每旬一次安全约束；错误返回、异常或直接改输入原子拒绝。失败不改AP、气力、经验、标记、RNG或已接受历史。

训练以执行前WAR求和与最大值计算：`D=min(100,20+floor(兵/2000))`；基础增加 `floor((WAR总和+最大WAR)/D)+3`。仅城市已完成练兵所时再取 `floor(基础增加×3/2)`；实增不超过气力上限与当前差额。通常上限100，熟练兵技巧16为120。

费用通常20AP，城市已完成军事府为10AP，金不变。每位执行者请求WAR经验2、功绩50，功绩库存上限60000；TP请求 `floor(实际气力增量/2)+5`，库存上限10000。气力与全部奖励、成长先算再一次提交，随后标记已训练/已行动；不能把请求量当成封顶后的实际增加。

## 2. 累计经验与成长

默认 `新XP=min(3000,旧XP+2)`，`新WAR=max(1,min(100,warBase+floor(新XP/100)))`。XP跨100/200不扣除100，能力达到100仍可积累XP到3000；XP满时合法训练的实得经验为0，其他奖励照各自规则处理。训练先读旧WAR再奖励，所以成长影响下一次训练。

3000/100给出的最多30点不是另一个可叠加培养余额。算术余数在3000为0，而源样本UI满格显示100，二者分开记录。warBase是未加年龄/宝物/官职/伤病的合成素质。本域只实现训练奖励的WAR；不实现五维研究、年龄变化、特殊人员getter或原存档导入。可替换成长参数须完整保存在profile中，不以自定义值冒充原作常量。

## 3. 第一军团AP恢复的有限选择

只选当前势力/军团据点；港关还须其母城在受控城市集合内。按据点统计己方身份0–3且实际在据点的武将，每据点最多10人，取人数最多的6据点，人数相同按ID稳定排序。**在城任务者计人数；在外、部队、俘虏不计**。君主/军师能力参数与人数过滤不同，在外仍可提供其角色参数。这是明确适配政策，不声称完整原人数selector已恢复。

- 君主项 `26+max(floor(max(统率,魅力)/5)−6,0)`
- 城市项 `min(10×(受控城市数−1),50)`
- 人数项为上述最多6据点人数之和
- 有军师倍率百分数 `70+floor(军师智力/2)`，无军师为100
- 核心恢复 `floor((君主项+城市项+人数项)×倍率百分数/100)`
- 然后加每个受控城市已完成符节台5点，不在加成后重新乘军师倍率
- 实际入账不超过255减当前AP；255是库存上限，不把180当PK统一硬上限

算式使用整数百分数，避免二进制浮点边界误差。原能力getter、极端跨军团港关母城关系仍保留证据限制。

## 4. EndTurn四阶段

先从当前快照计算完整计划，再按profile保存顺序执行：

1. advance-date：1→11→21→次月1，一年36旬
2. recover-ap：按上一节计划恢复AP，库存最多255
3. reset-base-training：清当前受控据点已训练标记，包含港关，不清外国据点
4. reset-officer-actions：清当前状态域武将acted，记录真正由true变false的ID

不修改武将任务、位置或身份，忙碌、在途、俘虏不会因清acted变成可训练。原研究恢复的是87建筑/1100武将全局重置链，本服务只适配自己的状态域；不等于原调度器，原后续任务链也可能重新置acted。月、季、年边界只是标志，不结算经济、AI、事件、衰老或任务到达。

替换turn adapter必须给四阶段的完整无重复排列；保存完整配置，不能只沿用同ID静默换规则。当前字段互不依赖不等于完整游戏可任意调度。

## 5. 随机、旧版本及证据边界

工程PRNG为可保存seed/draws的xorshift32，可显式替换；训练、AP、日历、当前成长及preview核心均不抽随机。原训练发言人随机选择/空槽重试明确省略为 `omit-training-presentation-v1`，因此核心0抽取不代表原全局随机流相同。

历史v1的“XP跨100拒绝”已由v2累计XP规则替代。显式v1状态迁移只接受旧默认profile与0–99XP，复制累计XP、以旧WAR作warBase，补旧切片原有现驻/无任务资格并记录legacy来源；不迁移/认证历史trace。无效资源、自定义旧profile、XP≥100或旧WAR0不静默修复。保存和重放必须核完整profile和派生值，非签名或反作弊。

来源等级是MOD关联source-local/compatibility-reconstruction，第二IDB有cap0/120等反例，不按文件名认定stock。Vanilla/主机版本不静默继承。P078及依赖、真实派遣/归还/捕获/归属/任务结算不在本规则中恢复；历史相邻研究只作来源记录。

本页为历史规则补齐，未运行测试、编译、演示或诊断；不把此前运行结果当成本次树验证，既有默认全套失败仍保留。
