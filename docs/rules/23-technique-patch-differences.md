# E8 技巧补丁版本差异

更新：2026-09-30。

E8 只处理同一技巧在不同 Windows 补丁、PK 与社区修复下的差异。结构化矩阵见 `docs/sources/technique-version-deltas.json`。

## 1. 官方版本链必须分开

Vanilla Windows 官方更新链至少为：

```text
1.0 -> 1.1 -> 1.2 -> 1.3 -> 1.3.1 -> 1.3.2 -> 1.3.3
```

官方 Ver1.1 页明确：1.0 更新到1.1；已经应用 Power-Up Kit 时不需要本体1.1更新。

官方 Ver1.2 历史明确写了“攻击等造成的伤害平衡”等调整，但没有逐技巧列出常量。

所以可以确认 Ver1.0 与后期资料存在技巧差异，但不能仅凭官方 changelog 判定每个数值究竟在1.1还是1.2改变。

PK Windows 是另一条链：

```text
PK 1.1
PK 1.1.1
```

官方 PK 1.1.1 修复兵粮消耗/预测兵粮、怒髪有时不发动、贯矢不加技巧P等问题，没有列出枪兵锻炼/精锐/云梯/工兵育成等技巧常量重平衡。

社区逆向常称目标为 `PC-PK1.1`；官方日文更新页写 `Ver1.1.1`。没有对应地区二进制hash前，不假定所有发行版字节完全一致。

## 2. Vanilla Ver1.0 到后期的明确技巧差异

2008《技术详解》明确记录：

| 技巧 | Ver1.0 | 后期资料 |
|---|---:|---:|
| 枪兵锻炼 | 伤害+20% | +10% |
| 精锐枪兵移动 | +2 | +6 |
| 精锐戟兵移动 | +2 | +6 |
| 精锐弩兵移动 | +2 | +6 |
| 云梯 | 攻城伤害+20% | 约140% |
| 工兵育成 | 耐久回复400% | 250% |
| 防御强化 | 据点反击120% | 200% |

这些是明确的“1.0 vs 后期”差异。

### 不过度推断其他兵科锻炼

戟/弩/骑Lv1后期资料都写当前10%，评论常说“同枪兵锻炼”，但只有枪兵锻炼条目明确附了 Ver1.0=20% 的注记。

所以当前只把 ID0 的1.20写成明确1.0差异，不自动把 ID4/8/12也改成1.20。

## 3. 不能把“后期”粗暴等同于“Ver1.2”

2008文章提到Ver1.2 AI行为，官方1.2也写“伤害平衡调整”，但官方说明没有逐项写：

```text
枪兵锻炼 1.20 -> 1.10
精锐枪移动 2 -> 6
...
```

所以数据层保存 `transitionPatch=unknown`。要确定1.1/1.2具体分界，需要 Vanilla 1.0/1.1/1.2 EXE 做地址级二进制diff。

## 4. PK逆向基准不能被Vanilla 1.0覆盖

本项目 PK reverse 基准：

```text
兵科锻炼伤害 1.10
精锐伤害 1.15，覆盖1.10
精锐基础攻防 +10
精锐枪/戟/弩移动 +6
精锐骑移动 +2
良马 +4
军制改革 +3000
云梯：普通陆军对建筑1.4，兵器/舰船1.2
车轴 +4
防御强化反击 ×2
木牛流马 +3
```

如果 ruleset=`pk-pc-reverse`，不能拿Vanilla 1.0的“精锐枪移动+2”等覆盖它。

## 5. 工兵育成：PK1.1倍率现已从原函数闭合

`00599710 每旬设施耐久恢复` 直接区分两类。

### 内政设施

有工兵育成：

```text
基础恢复相关量 ×0.30
```

无工兵育成：

```text
基础恢复相关量 ×0.15
```

所以同条件相对倍率精确为：

```text
×2
```

### 城市 / 港 / 关

无工兵育成路径最终还有：

```text
×0.4
```

有工兵育成则不做这次衰减，因此相对倍率：

```text
1 / 0.4 = 2.5
```

所以 PK1.1 fidelity 应写：

- 内政设施恢复×2；
- 城市/港/关恢复×2.5。

攻略后期“250%”只准确概括了固定据点支路。

Vanilla Ver1.0 的“400%”是攻略明确记录，但没有二进制支路细分，不能反推出1.0内部设施/据点公式。

## 6. 云梯也必须按版本和兵种分支

攻略回顾：

```text
Ver1.0：增加伤害20%
后期：攻城约140%
```

PK1.1原函数更细：

```text
剑/枪/戟/弩/骑 对建筑 ×1.4
兵器/舰船 对建筑 ×1.2
```

所以不能用一个“云梯=1.4”覆盖所有版本与兵种。

## 7. 防御强化版本差异很清楚

```text
Vanilla Ver1.0：反击120%
后期：200%
PK1.1逆向：×2
```

PK地址 `005B112A / 005B1140` 再次确认后期2.0。

## 8. 爆药炼成是原BUG vs 社区修复

PK1.1逆向资料明确：

```text
005B1236 练成炸药(31)
```

设计意图是点火方拥有爆药炼成时火伤增强。

但研究目标二进制实际把判定对象弄反，相当于：

```text
被烧的一方拥有爆药炼成
-> 被加重火伤
```

社区修复地址：

```text
005B1227
005B1239
```

修复后才变成：

```text
点火/攻击方拥有爆药炼成
-> 火伤增强
```

因此：

- `pk-pc-reverse`：保留原BUG；
- `pk-pc-community-fixed`：显式启用修复。

官方PK 1.1/1.1.1更新清单没有列这个BUG修复，目前也没有证据证明官方某地区后续发行版静默修掉它。

## 9. 矢盾/大盾挡战法同样属于社区修改

地址资料明确给出：

```text
矢盾对战法有效：修改 005AE01B
大盾对战法有效：修改 005AE083
```

反向说明原版默认不挡战法。

因此：

```text
official/fidelity: shieldsBlockTactics=false
community-custom: 可选true
```

不能把SIRE开关当作官方补丁行为。

## 10. 官方补丁与研究者“修改代码”分层

逆向文件中出现 `【修改】`、`修复BUG`、`可设置参数` 的代码，默认归入 community patch。

只有：

- 官方 GameCity 更新说明；
- 对官方版本二进制的直接diff；
- 或同版本原指令本身；

才能进入 official/fidelity profile。

## 11. 推荐版本profile

- `vanilla-pc-1.0`：只覆盖有明确1.0证据的差异。
- `vanilla-pc-late`：后期Vanilla Wiki/攻略值；1.1/1.2具体转折仍未知。
- `pk-pc-reverse`：本项目逆向目标，保留原BUG。
- `pk-pc-community-fixed`：显式修BUG模式，不再宣称原版fidelity。

实现层必须至少使用：

```text
rulesetVersion
patchVersion
fixProfile
```

而不是只有 `vanilla|pk`。

## 12. E8 当前结论

已锁定：

- 官方Vanilla与PK更新链；
- Vanilla 1.0→后期的7条明确技巧差异；
- 精确转折补丁仍未知；
- PK1.1工兵育成：内政设施×2、城市港关×2.5；
- PK1.1防御强化×2；
- 爆药炼成原BUG方向与社区修复方向；
- 矢盾/大盾挡战法属于社区patch；
- 官方与SIRE/修改器代码必须分profile。

仍open：

1. Vanilla 1.0/1.1/1.2技巧地址二进制diff；
2. 戟/弩/骑Lv1在Vanilla 1.0是否也为1.20；
3. Vanilla 1.0工兵育成400%的内部双支路；
4. 爆药炼成BUG是否被某地区官方后续发行版静默修复；
5. 主机版逐项技巧常量差异。
