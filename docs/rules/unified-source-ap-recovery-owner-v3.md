# T15 source-formula AP recovery, single-owner v3

## Capability and actual source
Append optional `apRecoveryConfig:{profile:'single-city-first-corps-source-ap-v1',adviserId:null|homeOfficerId}`. It requires the existing PK current-facts and research capabilities; no count, leader stats, percentage, bonus, AP override or recovery amount is accepted from a command. The immutable adviser ID must already belong to the current same-owner city roster. This profile models the existing single synthetic corps as the first corps and the existing city as the sole owned population base. Repair-site abstractions, field actors, transports, foreign encounter cities and scenario labels are not counted as additional cities or population bases.

The internal leaf constructs a validated, read-only synthetic GameState projection and directly invokes existing `calculateApRecovery`; it does not invoke EndTurn or a second world engine. The four source inputs are ruler max(leadership,charisma), owned city count, per-base officer count and adviser intelligence. Security is **not** an input. The original integer order and source calculation receipt are preserved rather than replacing the source with a copied formula.

Current ruler base-PK leadership/charisma is taken from the actual fixed ruler ID even when that person is deployed/away; deployment is not a ruler-identity change. The sole city's officer count derives from the current home roster with resident role, available and not-away; acted or job reservation does not remove a person from the count. This finite eligibility-to-count mapping is a named scenario compatibility inference, not proof of a complete native world census. A fixed optional adviser contributes only when current resident/available/not-away; otherwise the profile's explicit no-adviser branch is used. The actual engine validator's present-adviser intelligence domain remains enforced (no silent clamp).

No modeled facility is a verified talisman platform, so this profile supplies zero such platforms and exposes no fabricated platform count. Read-only GameState fields not read by the AP kernel use explicit neutral projection values and are never returned as an authoritative world state or copied into balances, traits, date or RNG. The helper rule documents this projection boundary.

## One writer and sampling phase
For an accepted outer WorldTick, the root samples current owner facts, role/travel state, AP and date **before** that Tick's clock advance, job completions, travel arrivals and later monthly phases. It calls the pure AP proposal once for this Tick, then passes a private typed proposal to the existing `advanceShared` transition. That transition verifies the proposal's AP-before equals its sole current ledger, advances the same clock once, and replaces its existing +20 request with the actual source request through the unchanged cap-255 writer. There is no second recovery after city settlement and no second AP ledger.

The receipt retains the actual writer before/request/after/delta/discarded/cap and adds source calculation evidence plus sampled turn/date. Full-cap recovery may have actualDelta zero; requested recovery is not credited as if it had survived truncation. Subsequent jobs, city/resource commands, payroll and other bridges read the same resulting AP owner. Failure of this or any later phase rejects the whole outer Tick.

When the profile is absent, the original fixed20 policy, receipt shape, optional root fields and default behavior stay unchanged. The legacy scenario policy remains the legacy default; the explicitly enabled private timeline records its source profile on the actual writer receipt rather than falsifying old scenario policy history.

## Replay, budget and accounting guard
Only immutable genesis plus exact typed outer history is saved. The private proposal is recreated from current replay facts, not accepted from a caller, saved snapshot, trusted token or arbitrary delta. Initial capability validation may call the pure leaf without writing any AP; only WorldTick can consume the resulting recovery request. Old standalone save/load paths cannot enable this private mode by forging a receipt.

The old city subhistory budget guard used `initialAP + 20 * advances`. Under this profile it instead sums the **actual** AP deltas of already reconstructed Tick writer receipts, once per Tick. This remains a necessary upper bound for paid city actions, not a claim to prove every bridge expense by that shortcut. All other costs are still validated and applied by full outer replay against the one current AP ledger. Existing command limits, 24 paid city-step cap, job/travel tail reservations and finite horizon remain unchanged.

No troop/person terminal, real-person ownership, P078, Closing, AI or extra calendar is added. This is a finite source-formula consumer with explicitly mapped scenario facts, not native campaign recovery coverage. Local candidate only; no tests, typecheck, build, candidate execution or remote writes.
