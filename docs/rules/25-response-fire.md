# E10 应射

更新：2026-09-30。主目标版本：PC-PK1.1；主机版差异单列。

## 1. 原地址与证据边界

弩兵系 Lv2“应射”：

```text
techniqueId = 9
00584DC8 = 还射 / 应射
```

这个地址在 PC-PK1.1 原地址表中已经锁定。

但当前公开逆向资料尚未给出 `00584DC8` 周边完整 caller 的逐指令文本，因此 E10 必须区分：

- PC地址级确认：技巧ID9与原判定入口存在；
- 长期实机高置信：哪些箭类攻击触发、射程/地形/支援边界；
- 仍open：PC内部 attack-type / unit-type 的精确比较指令。

## 2. 核心语义不是“所有远程攻击都反击”

日文 Wiki 的定义：

```text
弩兵受到弩攻击时反击
```

长期实测进一步表明实际触发集合是“箭类攻击”而不是所有 ranged damage。

确认/高置信包含：

- 弩兵间接普通射击；
- 骑射；
- 舰船的间接箭类普通攻击；
- 弩兵战法，包括火矢、贯矢、乱射；
- 井阑/舰船等的火矢类战法。

因此不应实现成：

```ts
if (incomingAttack.distance > 1) response()
```

而应实现成“攻击类型属于箭类 + 防守单位满足应射条件 + 能合法反击”。

## 3. 防守方必须是可应射的弩兵部队

攻略和 Wiki 都明确把效果主体写作“弩兵部队”。

当前 fidelity 规则：

```ts
defender.force.hasTechnique(9)
&& defender.currentCombatProfile === CROSSBOW
&& incomingAttack.isArrowFamily
&& canLegallyCounter(defender, attacker)
```

水上进入舰船 active profile 后是否仍读取原陆上弩兵兵装，PC逐指令尚缺；不要未经证据强制开启水上应射。

## 4. 应射不是无限射程

历史实测给出的典型“不触发”原因：

> 敌方已经研究强弩，从我方射程外攻击。

这意味着应射必须先满足：

```text
防守方能合法攻击攻击者所在格
```

所以：

- 普通弩兵射程2：攻击者在3格外时不能凭空打回去；
- 防守方拥有强弩时，当前合法弩射程扩大，回应范围也随之扩大；
- 不给应射单独造无限或固定3格射程。

## 5. 地形合法性同样会卡应射

历史日志明确讨论：

- 攻击者站在森林；
- 防守应射弩兵没有“射手”等允许攻击森林的能力；
- 因此无法合法对攻击者反击。

所以应射复用正常攻击合法性，不绕过地形限制。

## 6. 火矢和弩兵战法可以触发

Wiki《戦争》明确：火矢通常不会受到反击，例外就是拥有“应射”的弩兵。

2008 中文技术详解也写“只限弩兵队，包括战法”。

因此“应射只反普通攻击，不反战法”是错误实现。

## 7. 贯矢 / 乱射与邻接目标

历史实测记录：

- 应射并不保证永远是弓箭形式；
- 当应射弩兵因为邻接敌人的贯矢/乱射等成为卷入目标时，可能出现近身形式回应。

核心更像：

```text
获得一次合法反击机会
```

而不是固定“无论距离都发一箭”。

该细节目前仍是历史实测层。

## 8. 支援攻击明确不触发应射

历史实测直接写：

```text
支援攻击时，应射不发动
```

因此：

```text
incomingAttack.kind == SUPPORT
=> no response-fire
```

这与支援攻击本身“不遭反击”的规则一致。

### 8.1 应射还会反向影响攻击方的支援判定

Wiki《支援攻击》细测确认：

对拥有应射的敌弩兵做“间接普通攻击”时，攻击方支援攻击不发动。

但是：

- 近接普通攻击；
- 近接战法；
- 间接战法；

仍可正常触发攻击方支援。

目标混乱/伪报、无法正常反击时，间接普通攻击的支援又可以恢复。

说明应射/反击资格参与了攻击流程分流，不能简单在所有攻击结算完以后再补一发伤害。

## 9. 混乱 / 伪报时不能正常应射

既有异常规则已确认：

```text
混乱 / 伪报 -> 不能正常反击
```

支援攻击实测也与此一致。

所以当前高置信：

```text
confused || falseReport
=> response-fire disabled
```

## 10. 急袭可以规避应射伤害

Wiki 特技实测明确：

```text
急袭：
陆上攻击时50%不受反击伤害
也能50%规避应射伤害（PCPK）
```

这说明应射伤害在战斗层属于反击伤害，不是独立 true damage。

## 11. 连战的链式互动

Wiki 技巧页说应射属于连战的作用对象；PS2PK 历史实测甚至出现：

```text
双方都有应射 + 连战
-> 连续互相还射多次
```

但 PC-PK1.1 的精确连锁顺序/最大深度尚未从 caller 恢复，因此不把“约10次”写成 PC 固定上限。

## 12. 水战边界继续保守

历史讨论把“海战情况下也能应射、且不限弩兵”当成改造后的技巧设想，这反向说明原版至少不是“所有水军都能应射”。

当前 PC fidelity：

- 陆上弩兵规则确认；
- active naval profile 是否保留原陆上弩兵应射：open；
- 不用社区改造建议覆盖官方行为。

## 13. E10 当前证据分级

### PC reverse/address-level

- 技巧ID9；
- 原判定地址 `00584DC8`。

### documented / empirical-high

- 防守主体是弩兵；
- 弩/箭类攻击触发；
- 火矢与弩战法可触发；
- 骑射、舰船箭类攻击可触发；
- 必须能合法攻击攻击源；
- 超射程/森林非法目标会阻止；
- 支援攻击不触发应射；
- 混乱/伪报不能正常应射；
- 急袭50%可回避应射伤害（PCPK）；

- 每种战法的 primary / collateral 细分；

## 14. 兼容实现结构

在完整 caller 恢复前，兼容实现建议：

```ts
if (
  defender.force.hasTechnique(9)
  && defender.currentProfile === CROSSBOW
  && incomingAttack.isArrowFamily
  && incomingAttack.kind !== SUPPORT
  && !defender.isConfused
  && !defender.isFalseReport
  && canLegallyAttack(defender, attacker.position)
) {
  performCounterattackUsingNormalLegality()
}
```

`isArrowFamily` 与水上 profile 必须可版本化/替换；这只是按现有证据重建，不冒充完整 `00584DC8` 反汇编。

## 16. P0-17：应射与连击方向性补充

详见 `52-response-fire-double-strike-exactness.md`。

PC-PK1.1 地址表新增一条关键精确边界：

```text
00586E12 对弩兵(3)间接攻击时连击无效
00586F0F 连击50%，战法失败后的攻击也有效，连击不对应支援攻击
```

因此必须区分：

```text
主动方连击：
  间接攻击弩兵时被抑制

应射方连击：
  历史实测/原版规则说明确认还射本身可触发连击
```

两者不能共用一个“hasDoubleStrike -> roll50” gate。

当前仍不能从 `00586E12` 单独证明它是否显式检查 technique9；完整 `00584DC8` caller 仍 open。
