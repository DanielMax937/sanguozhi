# Single-roster F + H: status, entry and fixed environment events

This candidate cumulatively extends the separately frozen F optional encounter implementation. It does not edit F or PK frozen directories. The same cultivated field v4 module owns all identities, roles, troops, energy, positions, movement budgets, fires, action locks and condition. No second battlefield, per-cast persistent snapshot, global world or automatic AI is introduced. Old optional capability **absence stays absent** on save: absent encounterConfig/hazardConfig are internally read as disabled but not inserted as null. Explicit null stays null. Ordinary old Move commands retain their original field shape. Older defaults remain opt-out.

## Config and precise ownership
The sixth optional create argument is the F encounterConfig (independent enemy genesis/total troop budget, home-only top-level templates, both-side fixed combat geometry/panels); the seventh is optional `hazardConfig:{rockfalls:[{id,footprint}]}`. Empty rockfalls enables status/entry/recovery without environmental events. Config accepts at most16 unique fixed rockfall IDs and supported nonfacility footprints. No action may add a hazard, change its footprint or generate new enemies. Each rockfall is a single-use explicit environmental event, not a general/warrior spell; this trigger contract is named synthetic inference, not a recovered original caller.

F enemy ownership, initial exact-sum budget, neutral plain combat map and home-only city/PK binding restrictions remain. Output homeActorIds/enemyActorIds enables outer owner checks. World route integration must reject enemies from every home city action. No implicit food stock is created. F normal Attack now uses the same generalized private actual-kernel adapter as FalseReport, preserving positive damage and status-aware response eligibility.

## One condition, one action clock
Internal deployed state contains only `condition:{kind:'normal',remaining:0}|{kind:'confused'|'false-report',remaining:1..3}`. `confusedTurns` is output-only derived compatibility (0 unless confused); never an additional saved or independently decremented counter. Cast/Move/Return eligibility reads condition. Existing inferred Cast rejects false-report targets rather than projecting them silently as normal. Existing sorcery writes confused into the same condition. No unsupported replacement is guessed.

`FalseReport{actorId,targetId,draws:[{stage,bound:100,value}]}` requires encounter + hazards capability, available deployed actors on opposing explicit owners. The reused actual field combat kernel provides complete legality, energy15, acted lock on miss as well as hit, actual intelligence/charm formula, independent hit/critical/duration sampling and status replacement restrictions. Intelligence and charisma are currentFacts, not fixed template shadows. The neutral profile remains calm temperament, no actual special skill mapping/techniques, resolved panels; its fixed eligibility is an explicit bounded scenario, not full original tactical eligibility.

Evidence: repository `docs/rules/06-strategy.md` records pseudoreport energy15 and empirical formula. More importantly, actual `field-combat-lifecycle.ts` read at Git blob **2d540284a44384833e01ff823571b07820c1111f** already implements `false-report-status`: strategy.hit → on hit strategy.critical → strategy.duration. The earlier proposed new inferred probability is withdrawn in favor of this stronger existing caller. The helper accepts only exact actual stage tape, validates full consumption (no extra samples), and never reuses duration as hit or invents draws on deterministic rate0/100. A miss typically requires only actual hit draw; successful branches require whatever the real kernel consumes. Source bounds/fees/condition gates remain authoritative. Status changes do not migrate officers, dissolve units or call a return finalizer.

## Atomic FieldTick phases
With hazard capability: actual fire lifecycle first resolves current stationed fire damage and lifetime using current roster and the exact supplied fire samples. A new private `projectRosterRecoveryAfterFire` receives those actual resulting troops, current turn and actual remaining fire-cell set, with a matching settledFirePhase descriptor `{turn,actorIds,actorTroops,remainingFireCellIds}`. This is an internal typed phase consistency check, not independent authentication; only the enclosing reducer constructs it from its successful fire result.

The status phase invokes actual `terrain-hazard-lifecycle` resolveTurn/beginTurn on a deliberately status-only projection (`fires:[]`), not a claim that the environment had no fire. No second burn occurs. ID-ascending unit processing and lexical shortest-path tie breaking reuse the existing safe retreat helper. Unacted false-report units move at most one step toward their fixed template entry; a unit already there remains there. BFS uses the **real post-fire-lifetime** remaining fire cells and current serial occupancy. Starting on a still-burning cell is permitted after its one stationed burn; entering another still-burning cell is forbidden. A just-expired cell is available. ResolveTurn applies the actual countdown once, then beginTurn resets acted; the previous inferred effects advance is not also run. Movement budget resets once per shared Tick. No city entry/return is performed at a goal.

This phase order is a named synthetic composition, not verified native scheduling. Unsupported/unreachable retreat, insufficient positive troops or any phase failure rejects the **entire** field/outer Tick, including fire damage/lifetime. No silent fallback teleport or partial fire commit. Occupied/unreachable goals may need another legal actor action before a Tick is supported. The outer PK ordering remains field action → effective facts sync → completion resident acted lock.

The whole path and damage proposal are derived from the same before-state, then committed once to the same cellId/troops/energy/acted/budget.

If any visited/start cell has active fire, use the already reviewed **named neutral per-visit** fire-entry leaf: each entered active-fire visit consumes one matching sample0..200, damage300+draw, duplicate path cells retain exact index, initial starting cell is not an entry event. Fire IDs/lifetimes are unchanged; no spread/reignition. This is explicitly inferred, not recovered native entry caller. Nonneutral modifiers are not silently supplied: this bounded scenario enables only the fixed no-fireGod/no-rattan/no-explosives/no-critical profile, and current skill metadata does not claim those effects. Mixed nonplain terrain/fire rejects rather than omitting one hazard.

Without active fire, use actual `projectRosterTerrainEntry`/old terrain kernel with exact terrain samples and neutral traversal/antidote/difficultMarch traits. Unsupported costs/terrain contexts continue to reject. Encounter-enabled F remains plain-only; hazard-only home map can use supported nonfire terrain as allowed by its existing supplied-map and actual hazard kernels. No arbitrary terrain damage is invented.

## Rockfall, budgets and replay
`Rockfall{hazardId,draws:[{targetId,draw0..999}]}` resolves all currently deployed occupants of the configured footprint, including either owner, in exact ascending unique target ID order. Traits are explicitly neutral pathbreaker=false. Empty target set, incomplete/extra/order-mismatched draws, repeated hazard, zero/terminal troop effect or budget overflow rejects all. Actual multi-rockfall damage leaf is reused; no buildings, new disasters, actor energy charge or troop creator is implied by the environment trigger.

The same 256 cumulative hazard counter includes stationed fire targets, per-visit fire exposures, rockfall targets and actual nonfire terrain RNG events. Legacy fireDamageEvents output is an alias for this broader shared counter; hazardEvents makes its meaning explicit. consumedRockfallIds derives from history. All actions share the existing32 outer/field journal slots. No second RNG seed or independent timeline; all stage/value samples live in the single typed history. A failure in any leaf rolls back its movement, resource, action, status and event-ID effects.

Remaining outside this module: public world command integration/authority validation; home payroll/food/office resources; advanced skills/aptitudes/panels; mixed-fire nonplain path policies and unsupported retreat cases; original map/AI/real ownership; P078, Closing, injuries, rewards and zero terminal effects. No tests, code execution, build, typecheck or remote writes were performed.

## Explicit neutral skill guard correction
Attack/FalseReport reject when any currently deployed actor has nonnull currentFacts.skillKey, rather than silently passing learned skills as an empty complete list (including possible supporting actors). FalseReport additionally rejects either participant's immutable immune/guaranteed/beauty flags. These generic flags cannot be guessed into specific original skills. A completed skill cultivation may therefore make this neutral combat profile unsupported; it is not proof that every passive was integrated. Current numeric stats are still consumed; actual named-skill mapping remains explicitly open.

Explicit hazard genesis now preflights every actual home/enemy template entry as terrainInfoU32==0, matching the neutral retreat goal domain. Unsupported nonplain bases reject before any deployment or turn, rather than admitting a world whose ordinary Tick cannot run. Supported nonplain transit cells remain subject to actual movement/hazard kernels.
