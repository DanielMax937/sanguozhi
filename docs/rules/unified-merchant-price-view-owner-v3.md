# Unified merchant price-only effective-politics view (opt-in v3)

## Evidence and named inference
The unchanged `city-merchant-lifecycle.ts` reducer and `city-merchant-politics-v1.json` catalog accept politics 20..100 and retain their observed anchors, exact rational interpolation, buy-ceil / sell-floor rounding, eligibility, 20 AP charge, once-per-turn use, and +5 politics XP. T28/PK current effective politics can instead be 0..255. The new named policy `inferred-merchant-politics-endpoint-saturation-v1` supplies `max(20,min(100,effectivePolitics))` **only to the merchant pricing frame**. This extension is an explicit compatibility inference, not evidence that the original game clamps equipped politics this way.

## Actual owner connection
Append optional `merchantPricingConfig:{profile:'inferred-merchant-politics-endpoint-saturation-v1'}` after `starvationConfig` in the existing mobile-world / private timeline creators. It requires the existing effective-attributes and research capabilities. Omission keeps the old behavior, schema shape, and receipts; no default field is inserted. The exact config is retained in immutable genesis and validated again on complete replay. Unknown fields and unsupported/missing capability combinations reject.

The private research extension conveys only a boolean capability, never a caller-supplied politics number. `effectiveSyntheticScenario` already derives the current PK + live treasure projection from the sole owner. For a BuyFood/SellFood step only, `merchantFrame` applies the scalar helper to every officer's politics to maintain one consistent before/after pricing frame. The current internal `reduceMerchantTrade` checks the selected actor's politics range; the legacy lifecycle parser validates the complete roster. These distinct validation layers are not conflated. Identity, force, location, availability, acted state, XP and all eligibility data remain unchanged. Non-merchant domestic frames do not use the pricing adapter.

Both the before frame and the exact post-reducer whitelist re-projection use the same pricing view. Thus another out-of-domain roster member cannot invalidate only the second projection, and no changed identity/property can hide behind the view. The selected officer's receipt contains `effectivePolitics` and `pricePolitics` separately with `nativeEquivalent:false` / `personAttributesWritten:false`. Existing merchant audit `politicsEffect.politics` and `politicsXp.politicsBefore/After` describe the pricing view, not a mutation of the character's actual politics.

Only the original reducer's gold, food, AP, merchant-used marker, selected politics XP and acted marker are committed. Candidate-frame politics is never copied into genesis, base talent, effective attributes or progression. The existing outer atomic journal and post-command PK/effective synchronization remain authoritative. Within an existing city instant batch, its established projected-stat snapshot remains fixed for that batch; this policy does not add mid-batch recomputation or a new clock. Failure of any projection, qualification, resource check, equality check, later owner invariant, or output budget rejects the complete outer command. No second balance, save format, RNG or independently spendable ledger is introduced.

## Boundaries and price-risk disclosure
For effective 20..100 this pricing projection is identity. Values below/above use the existing lowest/highest anchor; anchors and upper price-effect bound are not increased. **This is not a no-arbitrage guarantee**: the existing highest catalog effect (approximately 1.142868) can already give a positive unrounded same-UI buy/sell round-trip factor (`0.8 * effect^2 > 1`). Existing rounding, stock, AP, turn and merchant constraints still apply; this batch does not redesign that observed pricing model.

No native-map proof, real-person mutation, injury/death, zero terminal, P078 or Closing behavior is added. This local candidate depends on the frozen repair/starvation owner batch and its predecessor chain; it is not yet remotely published. Static review only; no tests, typecheck, build or candidate execution was performed.
