# E4 训练效果与气力

更新：2026-09-30。主目标版本：PC-PK1.1。

## 1. 结论摘要

E4 已把此前 open 的“单次训练到底加多少气力”恢复为原函数公式。

训练命令只读取最多3名执行武将的**武力**，不读取统率。当前据点兵力越多，单次训练效果越低；PK城市存在练兵所时，在基础训练结果上再乘1.5。

## 2. 据点气力上限

PC-PK1.1：

```text
无熟练兵：100
有熟练兵：120
```

`00487010 GetSPMoraleLimit` 对城市、港、关使用同一上限规则；`00488010 IncreaseSPMorale` 增减据点气力时也再次按100/120封顶。

研究“熟练兵”只提高上限，不会把现有气力自动抬高；研究完成后仍需训练或其他方式把气力补到120。

## 3. 训练效果精确公式

来源函数：

```text
005C3F50 计算训练效果
```

设：

- `T` = 当前据点兵力；
- `W[]` = 1～3名执行武将的当前武力；
- `S = sum(W)`；
- `M = max(W)`；
- `cap` = 100 或 120；
- `current` = 据点训练前气力。

原函数中的 magic multiply：

```text
imul 0x10624DD3
取高32位
sar 7
```

对本作有效的非负兵力范围等价于：

```ts
floor(T / 2000)
```

因此：

```ts
denominator = min(100, 20 + floor(T / 2000))

baseGain =
  floor((S + M) / denominator)
  + 3
```

这里最高武力武将等价于**被计算两次**。

### 3.1 练兵所

仅城市可建练兵所。若训练发生在有练兵所的城市：

```ts
baseGain = floor(baseGain * 3 / 2)
```

即精确×1.5后取整数。

### 3.2 最终实际增加量

```ts
actualGain =
  min(baseGain, max(0, cap - current))
```

UI预览与实际执行都调用同一 `005C3F50`，随后执行函数再经 `00488010` 按上限处理。

## 4. 训练公式的行为

三个武力100的武将：

| 据点兵力 | 分母 | 无练兵所 | 有练兵所 |
|---:|---:|---:|---:|
| 0 | 20 | 23 | 34 |
| 5,000 | 22 | 21 | 31 |
| 10,000 | 25 | 19 | 28 |
| 20,000 | 30 | 16 | 24 |
| 50,000 | 45 | 11 | 16 |
| 100,000 | 70 | 8 | 12 |
| 150,000 | 95 | 7 | 10 |

因此旧 fallback `5 + floor(统率×0.15)` 不只是参数不准，**变量本身也错了**：原训练效果看武力、最高武力、武力和以及据点兵力。

## 5. 训练命令执行副作用

`005C4220 执行训练` 已确认：

- 最多3名执行武将；
- 每名有效执行武将：武力经验 +2；
- 每名有效执行武将：功绩 +50；
- 每名执行武将设为已行动；
- 据点写入“已训练”状态；
- 普通行动力消耗20；
- PK城市有军事府时行动力消耗10；
- 当前执行函数中没有扣除金钱的路径。

技巧点不是固定“+7～10”，而由**实际气力增加量**计算：

```ts
techniquePoints =
  floor(actualGain / 2)
  + 5
```

例如本来可训练+19，但据点从95只能升到100，则 `actualGain=5`，本次技巧点为7。

当前公开文本尚未完整展开 `005C4100` 的全部可执行资格检查，因此“满气力时UI是否直接禁用”等入口级 gate 不从结果函数反推。

## 6. 部队气力上限

部队自身也有独立气力 byte。

地址资料确认：

```text
00495441...  获取部队最大气力
00496490     SetTroopMorale
004964F0     AdjustTroopMorale
```

同样：

```text
无熟练兵：100
有熟练兵：120
```

气力当前值不会因为研究熟练兵而自动+20。

## 7. 野外每旬恢复

### 7.1 军乐台

原地址：

```text
00598B30 军乐台
0059A325 气力 +10
有效范围 2
```

因此己方有效军乐台范围内：

```text
每旬 +10
```

### 7.2 奏乐

```text
0059A2B1 奏乐
0059A40D 气力 +5
```

没有军乐台恢复时，奏乐每旬+5。

日文Wiki明确记录：奏乐与军乐台恢复**不同时叠加**。

### 7.3 诗想

```text
0059A2BE 诗想
0059A3C5 军乐台额外 +10
```

即在军乐台范围内：

```text
普通：+10
诗想：+20
```

诗想与奏乐同样不是额外再加+5。

当前可实现的恢复优先级：

```ts
if (inFriendlyMusicPlatformRange) {
  gain = hasPoetry ? 20 : 10
} else if (hasMusic) {
  gain = 5
} else {
  gain = 0
}
```

此前 provisional 的“城内驻军每旬自然+5”未找到对应原EXE路径，撤回；普通野外部队也不额外添加一个无来源的自然恢复常量。

## 8. 战斗中特技造成的气力变化

原地址与日文Wiki交叉确认：

| 特技/事件 | 气力变化 | 触发 |
|---|---:|---|
| 扫荡 | 敌 -5 | 攻击命中目标部队；支援攻击路径也有对应地址 |
| 威风 | 敌 -20 | 同上 |
| 昂扬 | 自身 +10 | 击破敌部队 |
| 怒发 | 自身 +5 | 受到敌部队战法 |

扫荡与威风同时存在时以威风为优先，不叠成-25；同名多人也不按人数重复叠加。

这些变化最终仍受部队气力的0和100/120边界控制。

## 9. 单挑相关气力变化

原地址资料还确认：

```text
单挑胜利：+15
单挑败北：-15
单挑被拒绝：提议方 +10
拒绝方：-5
```

单挑自身的斗志系统属于 `10-duel.md`，不要和地图部队气力混成一个属性。

## 10. 补兵与气力平均

已有长期实机资料确认：给部队补兵时，新旧兵力会按人数对气力做加权平均。

例如：

```text
2500兵，气力0
补到5000兵，新兵来自气力100的据点
=> 部队气力50
```

精确资源事务 caller 仍与E1补给流程一起保留待核，但不能实现成“补兵后气力不变”。
