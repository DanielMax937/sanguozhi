# 独立编成与能力面板的版本化规则

适用版本：PR #70 的 `o03-detached-reference-v1` 及明确提供完整表的替代profile。原作算术证据见[部队面板](18-unit-panels.md)、[副将取整](45-deputy-rounding-exactness.md)、[PC血缘三分之一边界](68-deputy-blood-third-pc-opcode-boundary.md)；接口、输入结构和存档合同见[工程文档](../engine/unit-formation.md)。本页记录服务实际计算规则，不把独立规格等同真实出征。

## 1. 成员和关系优先级

1–3名不同成员，第一名是主将，其余为副将。五维明确选择基础值或实际值，所有成员一致使用该选择，不将两套属性相加；适性C/B/A/S为0/1/2/3。技巧ID为0–35。关系由完整队内事实提供，不猜测人物数据库、宝物、伤病或原生关系helper。

队内任意两人存在任一方向的嫌恶边，五维全部采用主将值，其他关系不能覆盖；六适性仍逐项取全队最大。无嫌恶时，每个副将独立按夫妻→义兄弟→喜爱→血缘→普通选择除数1、1、2、3、4。统率/武力候选为 `主将 + floor(max(副将−主将,0)/除数)`，各候选与主将取最大，不叠加多名副将加成。智力/政治/魅力直接取全队最大，六适性亦取最大。

参考喜爱方向为副将→主将；`either-direction`是可替换的命名政策。夫妻/义兄弟/血缘是无向声明；嫌恶和喜爱是有向声明。血缘/3保留PS2经验及跨平台参考等级，不宣称PC完整/3指令体已经恢复。

相同最大值的来源ID全部保留，按UTF-16 code unit排序，不任意选一人或叠加收益；成员的主将/副将角色顺序仍保持原输入顺序。

## 2. 面板公式与精度

适性系数Q：C/B/A/S为7/10、8/10、9/10、1。剑固定3/5；运输走舸固定3/5，战斗走舸按水军适性。技巧3/7/11/15只分别作用当前枪/戟/弩/骑兵装1/2/3/4，在缩放前给基础攻防各加10，不对最终面板、建设或移动再加10。

- 攻击＝武力×修正基础攻击×Q×1/100×类型攻击倍率×状态倍率
- 防御＝统率×修正基础防御×Q×1/100×类型防御倍率×状态倍率
- 建设＝(政治×2/3＋50)×类型防御倍率×状态倍率
- 战斗类型攻/防倍率为1/1，运输为2/5与1/3
- 混乱倍率4/5，正常及伪报为1
- 最终先保证至少1，再向零截断；可大于100，不按byte回绕，也不施加上限

参考计算以约分BigInt有理数表达中间量。实验性 `stage-grid-trunc`在文档所列每次乘/加后向零截到1/grid，grid分母为1–1000000；最终转换相同，不改变关系整数除法。两种精度政策都不认证x87中间链。没有暗加兵数、气力、目标、地形或伤害系数。baseMobility只返回表值，不是移动预算或路径计算。

stage-grid的阶段顺序明确为：攻击/防御从对应属性开始，依次乘修正基础值、Q、1/100、对应类型倍率、状态倍率，每一步分别按grid截断；建设从政治开始，依次乘2/3、加50、乘类型防御倍率、乘状态倍率，每步分别截断。不是先计算完整表达式后只做一次grid截断；最后仍单独执行至少1和向零整数转换。

## 3. 编成容量与来源可行性

固有容量与当前来源可提供上限分开：`capacity`是固有值，`limits`是该值和来源可用资源的较小者。来源只有1兵可以预览1兵规格，但规格未来兵容量仍可能是10000。参考主将类别junior/standard/senior为5000/10000/15000，仅是明确供应的示例类别，非原生官职映射。

战斗兵容量只取主将类别，金10000、粮50000，货物为0。陆装必须选0–8，水装9–11，面板兵装必须为其中之一：枪戟弩马每请求1兵需1件并限制当前可行兵数；攻具5–8无论兵数需1件；楼船/斗舰10/11另需1艘，选舰船不免除陆装需求。剑0、走舸9为隐含装备，不要求库存。

运输使用陆装0/水装9，面板调用方明确选0或9。固有兵/金/粮容量60000/100000/500000，不用主将类别或货物量压缩兵容量。运输货物逐兵装独立，当前上限为 `min(profile容量, 来源库存)`；数量装参考上限每类100000，件数装每类100是明确工程政策，可由完整替代profile更换。0/9货物始终为0，货物不变成面板兵装。

不静默裁剪请求。按最低兵数/兵容量、金、粮、兵装0–11稳定列出全部短缺。数量装备短缺可同时出现在兵上限和装备需求中。零兵请求是合法但不可编成的预览，规格为空；超容量也返回不可编成及原因，不修改来源。能力计算允许12种兵装的数学域，不证明原生运输调用方使用全部兵装。

## 4. 政策保存、证据与排除

保留ID `o03-detached-reference-v1`要求完整参考内容不变；新ID可以使用明确标记的完整供应表。兵装、指挥类别、关系方向、精度、货物容量都属于版本内容，不能只改标签却暗换算法或用缺失表回落默认值。保存和重放从请求重算所有面板、来源、短缺及规格；其规范哈希是内容一致性，不是原生身份认证。

成功结果只是一份独立规格，不创建运行时部队、不扣兵金粮兵装、不迁移武将、不执行出征。P078及依赖和原生捕获/死亡/势力灭亡/归属/归还/任务终结等全部排除。

[来源清单](../sources/unit-formation-v1.json)保留source-local、跨平台参考和新政策等级。最终`_ftol2`向零转换已有源内依据；完整PC关系分支/方向、血缘/3、x87中间精度、clean-stock兵装表、官职/技术映射、运输面板caller与原生件数货运路径仍未证实。原43证据组不减少。
