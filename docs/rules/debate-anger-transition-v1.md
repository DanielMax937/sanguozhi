# 现代参考：愤怒结算至下一次出牌前的有界事务 v1

## 结论与证据边界

本版本把既有公开愤怒阶段核与既有公开回合衔接核组合成一笔有界数据事务：先完成实际的 `AngerPhase` 两轮上限结算；只有其最终结果确实非终局，才执行 `TurnEnd → TurnStart`，到达 `ready-for-play`。若愤怒阶段已判出胜者，则停在 `terminal-pending-classification`，不递减计时、不更新先手或话题、不清除已出牌、不补牌，也不调用终局分类或 Closing。

这不是完整普通回合、完整阶段机或新的旧会话版本。起点已经位于愤怒阶段入口，普通出牌、普通攻击、普通牌效果与前序状态均由调用者提供；本事务不补做 `ordinaryAttack`，也不把普通攻击模型当作兴奋态伤害适配器。

## 1. 入口检查点：明确收窄的工程准入

双方编号为 0、1。愤怒入口提供原 `firstTeam`，胜者必须为 `winner = -1`，两队初始 HP 均须在 1..1000。组合接受通用伤害断言 `genericOnly = true` 与非教程 `isTutorial = false`，不解析人物、性格来源、书籍或人物专属伤害 hook。

每队愤怒状态包含：已解析的 `timid / calm / bold / reckless` 性格、有效武力 1..100、HP、压力 0..100、兴奋计时 0..4、活动容量 4..7，以及完整七物理槽手牌。另有初始非活动连击检查点、两队崩坏层级 0..3、两队锁存崩坏标志、按队编号提供的有效攻击值 70..227、按愤怒轮次提供的抽样数组。

本组合进一步要求：

- 保留槽 0 必须恰为再考牌代码 0。
- 活动可出牌槽 `1..maxCardCount-1` 只能是空槽 −1 或牌代码 1..14，不能含 0；允许空洞、重复牌和未排序状态。
- 非活动尾槽仍可为 −1..14，不把尾槽预先清空，也不声明其一定可由完整原生历史到达。
- 初始连击必须 `active = false`；其 `attacker` 可为 −1、0、1，计数可为 0..7。若没有小心性格实际进入愤怒，保留原非活动字段；进入小心愤怒才重置连击攻击方及计数。

牌码约定：1..9 为三个话题各小、中、大牌；10 大喝，11 诡辩，12 无视，13 镇静，14 激昂；−1 是物理空槽，0 是再考。

衔接输入只补充愤怒核没有的状态：原普通攻击方 `attacker`（−1、0、1）、当前话题（有符号 32 位整数）、双方原 `playedCard`（−1..14）、`canRethink`、各自当前 18 张牌堆、游标 0..18，以及话题／补牌修补抽样。牌堆每项为 1..14。它不重复提供手牌、HP、压力、武力、计时或崩坏字段，避免调用者提交两套互相矛盾的实际状态。

这些是组合的工程接入条件，不是新增的原生玩法限制，也不是前序出牌合法性或全部来源状态可达性的证明。特别是单独的愤怒阶段核原有手牌域更宽，本版本不修改该核，而是明确拒绝不能安全桥接到既有当前牌堆 TurnStart 合同的初始手牌。初始正 HP、`winner = -1`、非教程和通用伤害同样属于本事务的路线限定；不把这些限定倒写为 C# 每个方法自身的 guard。

## 2. 愤怒阶段只能按固定两轮顺序完成

第一轮的顺序不可交换：

1. `CalcAngering(true)`，允许激昂反击。
2. 对实际进入愤怒者执行一次 `Anger()`。
3. 若产生待处理连击，完成整次小心连击。
4. 判定胜负。

第一轮已判出胜者时立即结束愤怒阶段：不执行第二轮，不计算崩坏。因此原崩坏层级和标志原样留下，崩坏收据为 `null`。

第一轮非终局才继续：

1. `CalcAngering(false)`，禁止激昂反射，但仍可被镇静压制。
2. 执行一次实际愤怒效果及整次待处理连击。
3. 计算两队崩坏。
4. 再判胜负。

没有愤怒候选也不能提前结束流程，仍应执行该轮后续的胜负检查以及来源规定的第二轮／崩坏步骤。最多两轮，不添加第三轮，不循环到“无人满怒”，也不在每一下伤害后自行抢先切换阶段。

### 2.1 候选与反击牌

每轮先检查 `firstTeam`，再检查对手；候选条件为未处于兴奋状态且压力已满。准入整数域内即计时 0、压力 100。双方同满时先手优先，不改按普通攻击方或连击攻击方挑选。

只有候选的对手计时为 0 才检查反击牌。第一轮先寻找激昂 14，若其首个活动区匹配下标严格大于 0，采用激昂并短路，不再查镇静；否则寻找镇静 13。第二轮不查激昂，只查镇静。既有核的规则是“首个匹配下标大于 0”，不是任意后续槽有同牌就能使用；本组合的槽 0 固定为再考，使槽 0 同牌遮蔽情形不在准入域内。

触发时按以下顺序修改压力并夹在 0..100：

- 无反击：候选压力减少 100，候选自己进入愤怒。
- 镇静：候选压力减少 50，移除对手该镇静牌，然后取消本次进入愤怒。
- 激昂：先令防守方压力减少 100，再令原候选压力减少 50，移除防守方激昂牌，然后把进入愤怒者改为防守方。重定向后不再次要求防守方压力达到 100。

反击牌移除发生在压力修改之后、重定向及 `Anger()` 之前；该空位会影响之后的真实补牌需求。

### 2.2 性格效果、移牌与小心连击

实际进入愤怒者的计时设置为：小心／莽撞 1，冷静／刚胆 4。冷静和刚胆在此步仅设置计时。小心设置 `combo.active = true`、连击攻击方为实际进入者、计数归零；莽撞立即对对手造成请求 HP 伤害 `200 + strength`，请求压力伤害为该请求 HP 伤害除以 15 后向零截断。

HP 写入夹在 −100..1000，压力写入夹在 0..100；先写 HP，再写压力。压力增量以请求伤害而非已夹取的实际 HP 损失计算。莽撞不调用普通攻击或普通攻击伤害 hook。

小心连击扫描当前可变手牌的物理下标 0 到活动容量减 1。读到 1..9 才攻击，每次实际命中恰消费一项 bound-5 抖动值。对该队给定有效攻击值 `A`、抖动 `r`、牌级系数 `L`，通用请求 HP 伤害为 `(A + r) × 10 × L × 10 / 1000` 向零截断；小／中／大系数分别 10、15、20，请求压力伤害再由请求 HP 伤害除以 15 向零截断。这里不推导 `A`，不运行人物专属 hook。

每次命中依次写 HP、写压力、移除当前槽、递增连击计数。源移牌先把指定槽写 −1，再清空全部七槽，仅将原活动区非空幸存牌稳定压紧到前缀；非活动尾槽不参与压紧而被清除。随后扫描下标仍加一，不回看刚移入删除槽的牌，因此连击不是“打出所有原话题牌”。空牌、再考与话术只跳过，不抽样、不伤害、不移牌、不加计数。对手 HP 到 0 或负数也不中断整次扫描；扫描结束后才清 `combo.active`，然后按阶段顺序判胜。

## 3. 胜者、崩坏与终局分流

胜负使用原愤怒阶段 `firstTeam`：先检查其对手 HP 是否不大于 0，是则先手获胜；否则才检查先手 HP，先手非正则对手获胜。一般规则中双方同时非正优先判给先手，但不把该分支存在误写为本版本正 HP 入口一定能到达该状态。收据记录实际短路检查，不能伪造被短路掉的第二个检查。

仅第二轮整次连击完成之后计算崩坏，之后才做该轮胜负检查。对每队计算 `(1000 − HP) / 250` 向零截断并夹在 0..3：新层级与旧值不同便写新值并把崩坏标志设为 true，层级降低也如此；相同则保留原标志，不将已有 true 归零。

最终有胜者时返回 `terminal-pending-classification`。来源会再依 `CanCritical()` 选择 Critical 或 Closing，但本组合明确不执行该选择，不推断追击／留情、胜利类型、奖励或强制结局覆盖。因此 HP 已到 −100 也只是终局待分类，不代表会心已执行。

终局路线还要求三组衔接抽样均为空：回合结束话题数组、队 0 补牌修补数组、队 1 补牌修补数组。即使抽样格式有效，也不能留给一个不会执行的未来阶段。其余衔接元数据仍需通过完整语法／域验证，但不据此执行当前牌堆可补足性检查、不减少游标、不消费牌；例如合法的游标 18 本身不使终局失败。

## 4. 两层状态如何衔接，哪些字段不能串用

整个事务有三个有意义的快照：初始状态、实际愤怒结束状态、最终状态。首先把愤怒输出的双方手牌、HP、压力、武力、性格、容量、计时及崩坏标志叠加到原补充元数据；两队崩坏层级和连击检查点仍来自愤怒核。

必须保持三个不同身份：

- `firstTeam`：愤怒候选优先与两次胜负检查所使用的来源先手。
- 原普通 `attacker`：此前普通对阵已确定的攻击方，供 TurnEnd 使用。
- `combo.attacker`：本次或既有小心连击的攻击方，只属于连击状态。

连击即使由另一方发动，也不覆盖普通 `attacker`。计时递减也不触发重新计算普通攻击方。双方原 `playedCard` 不取自当前压紧手牌、不用连击打出的牌代替，直到 TurnEnd 完成话题处理前始终保留。

非终局调用回合衔接后，只把该核负责的字段写回：先手、话题、计时、手牌、已出牌、再考额度、崩坏标志、牌堆及游标等。不得用较窄的衔接角色结构替换完整角色而丢失 HP、压力、武力；不得把 TurnStart 清零的崩坏标志误当作崩坏层级也清零。连击检查点与崩坏层级保留实际愤怒输出。终局没有第二层衔接写回，原补充元数据保持原值。

## 5. 仅非终局执行的 TurnEnd 与 TurnStart

### 5.1 TurnEnd

严格先递减队 0 正计时，再递减队 1 正计时；0 保持 0，每个正值减一。刚进入愤怒的小心／莽撞计时 1 在此变 0，冷静／刚胆 4 变 3；终局路线则没有这些递减。

随后检查原普通 `attacker`：

- 为 −1：跳过整段先手、普通牌话题与诡辩话题处理，原先手与话题保留；双方计时递减和之后 TurnStart 仍继续。
- 为 0 或 1：把先手改为该队。其原已出牌若为 1..9，按三张一组映射为话题 0、1、2。
- 同一个有效攻击方门内，扫描双方原已出牌。只要至少一队为诡辩 11，且对手不是无视 12，就恰消费一次 bound-3 话题抽样，并在普通话题更新之后写话题。双方都符合也只有一次抽样；抽到相同话题仍算发生了抽样与写入。

不能因为本回合愤怒者刚好是某队，便替换上述来源普通攻击方；不能在清空原已出牌后才计算话题。

### 5.2 TurnStart

完整完成队 0 的以下序列，之后完整完成队 1：

1. 原已出牌设为 −1。
2. 若崩坏标志为 true，则再考额度设为 true。
3. 若递减后仍是正计时冷静，则再考额度设为 true；否则保留额度，不主动写 false。
4. 调用既有当前牌堆补牌核。
5. 若递减后仍是正计时刚胆，按最终修补、排序后的活动手牌统计话题牌；只有最终计数为 0 才清计时。
6. 清该队崩坏标志，不清崩坏层级。

冷静计时 1→0 后不能只凭“性格冷静”恢复额度；2→1 则可以。崩坏恢复额度独立于冷静计时。刚胆判定不可拿补牌修补前的零话题计数代替最终计数：有空槽且补入全话术时，修补完成便有话题牌，应保留正计时；原活动手牌已满且全为话术时，没有新增槽可修补，刚胆才可能被清零。

补牌将槽 0 恢复为再考，按槽 1 起逐个填活动空槽 −1，每张消耗当前牌堆一项。若填完仍无话题牌且本次确实补过牌，恰消费一项 bound-9 修补抽样，将最后补入槽改为话题牌 `1 + value`，最后排序活动前缀。没有新增槽时不凭空修补。补牌本身保留非活动物理尾槽；这不撤销愤怒移牌已经清除的尾槽。

## 6. 必须依据实际愤怒后手牌判断当前牌堆能否接续

本事务只使用每队给定的当前 18 张牌带。非终局是否需要更多牌，要依据反击移牌和实际连击压紧之后的真实手牌，不能对愤怒之前的“已满手”先做一次可补足探测并当作最终结论。

- 游标 18 且实际没有活动空槽，可以继续；游标恰好消耗到 18，也可以成功。
- 反击消耗镇静／激昂，或小心连击消耗话题牌后产生空槽，可能令原本无需补牌的输入实际需要下一张。
- 如果实际补牌需要第 19 项，整笔事务拒绝，不回绕、不截短、不借用另一队牌堆，也不执行 `DeckGenerate`。
- 即使队 0 补牌已在隔离状态中成功，队 1 失败仍不提交队 0。即使此前愤怒和话题处理成功，后续补牌失败也不提交愤怒伤害、反击移牌、计时、先手、话题或部分收据。

固定 C# 在耗尽处会再生成；当前 18 牌范围是明确的工程边界，不是把来源行为改成“无法再抽牌”玩法。

## 7. 显式随机记录与完整嵌套审计

所有随机值由调用者作为有标签的结果输入，本事务不创建 RNG、不调用随机回调、不推进外部随机状态。三类数值分别是：

- 小心连击：`debate-timid-combo-jitter`，`bound = 5`，`value = 0..4`，按愤怒轮次给定。
- TurnEnd 诡辩话题：`debate-turn-end-topic-reroll`，`bound = 3`，`value = 0..2`，零或一项。
- TurnStart 每队补牌修补：`debate-fill-topic-repair`，`bound = 9`，`value = 0..8`，每队零或一项。

全局消费顺序只能是第一轮连击、第二轮连击、回合结束话题、队 0 修补、队 1 修补。第一轮终局没有第二轮；某轮未发生连击，该轮数组必须为空。第一轮终局时第二轮数组必须为空；终局时全部衔接抽样必须为空。非终局每个需求点必须恰有所需项，多给和少给都拒绝，不能为了凑齐记录而执行不存在的随机动作。

外层按公开核容量给出最多 11 项的保守上界：愤怒至多 8，衔接至多 3；这不是断言该严格准入域存在一条恰用满 11 项的可达原生轨迹。外层另记全局顺序、阶段与局部来源索引，完整保留愤怒核各轮、连击、移牌、压力／HP 写入、胜负、崩坏收据，以及衔接核与其 TurnStart／补牌的完整嵌套收据。不得为了统一索引而改写子核原有局部索引。

`externalRngConsumed = 0` 表示没有外部随机调用，不是说输入抽样没有被使用，也不是整个游戏零随机。上述有序输入记录不证明原生 PRNG 种子、原生全局随机调用次数、其他阶段消费或原生牌身份等价。

## 8. 原子安全与不可误认的结果

整个外层输入先安全脱离调用者对象，先解析衔接的完整静态字段与全部抽样语法／域；愤怒输入再由原公开愤怒核完整解析后实际执行。不会为了验证兼容性预跑一次后又执行一次愤怒，也不会预跑回合衔接来猜测之后的手牌需求。是否需要衔接以及其抽样需求，只依据这一次实际愤怒结果决定。

接口使用封闭字段集合与完整政策比对；未知字段、无效数值、稀疏数组、循环引用、非普通数据对象、访问器或可执行值不能作为状态。代理检测不可用时安全失败，不调用用户 getter、代理 trap 或函数。返回值脱离输入并递归冻结。

成功只可能有两个检查点：终局待分类或下一次出牌前。失败只返回有类型的原因；来自子核的失败保留阶段归属与完整失败原因，但不返回半状态、已成功的上游收据或任何外部状态变更。缺抽样、多抽样、未用衔接抽样、当前牌堆实际耗尽及后一队失败，都服从同一个整笔不提交原则。

`ready-for-play` 是工程检查点标签：代表此限定数据序列已完成，不代表已运行来源 phase 对象、UI 动画、事件回调、真实下一次出牌或完整场次。初始 HP／压力／已出牌等虽有数值验证，其前序来历仍由调用者负责。

### 8.1 实现中的合同名称

实际入口是 `evaluateDebateAngerTransition`，profile 为 `debate-anger-transition-reference-v1`，政策常量为 `DEBATE_ANGER_TRANSITION_POLICY_V1`。输入顶层为 `schemaVersion / profile / policies / anger / transition`；`anger` 必须是既有完整愤怒输入，不是预计算成功结果。主成功对象包含完整 `state`、`nextCheckpoint` 与 `receipt`。

主收据的 `before / afterAnger / after` 对应本页三个完整快照；`anger` 保存原愤怒核完整成功对象，`transition` 保存原回合衔接核完整成功对象或 `null`，不只保存其 receipt 摘要。终局 `transitionDrawOffset = null`；非终局该值为衔接开始前已消费的愤怒抽样数。`consumedDraws` 使用外层连续 `flatDrawIndex`，同时保留 `angerGlobalIndex / pass / passDrawIndex`，或 `roundTransitionFlatDrawIndex` 及原衔接的 `teamIndex / localDrawIndex / turnStartFlatDrawIndex` 等适用字段。主收据还保存 `drawCount / nextCheckpoint / externalRngConsumed`。

不合格初始手牌以 `invalid-initial-hand` 拒绝，容量不合格为 `invalid-initial-hand-capacity`；实际终局仍携带衔接抽样为 `unused-transition-draws`。原愤怒失败包装为 `anger-phase-failure`，原回合衔接失败包装为 `round-transition-failure`，各自 `dependencyFailure` 保留原失败对象，包括原有轮次或子核原因。完整字段、其他拒绝代码和输入预算以配套接口合同与实现为准，不把这里的例示列表误当作可接受字段全集。

## 9. 关键人工纸面推导

以下只是选取字段的人工推导，不是执行输出，也不是可省略完整政策和其余字段的请求示例；完整输入须满足前述全部准入条件。

### 9.1 第一轮终局不能顺手做回合结束

原先手为队 0，两队都未兴奋且压力 100，均无反击牌；队 0 是武力 100 的莽撞，队 1 初始 HP 200。队 0 请求伤害 300，把队 1 HP 夹到 −100；队 1 原压力 100 仍为 100。第一轮判队 0 胜，队 0 新计时保留 1，队 1 不执行第二轮愤怒。

若原崩坏层级为 `[2,0]`、标志皆 false，它们原样保留，即使这些层级与当前 HP 不一致也不在此时补算。原已出牌 1、2 及合法游标 18 都不改。结果是终局待分类，不是回合开始完成，也没有会心结果。若再附任一有效格式的衔接抽样，应整笔拒绝而非默默丢弃。

### 9.2 第二轮终局必须留下已经计算的崩坏

原先手队 0 是冷静、HP 200、压力 100；队 1 是武力 100 的莽撞、HP 1000、压力 100；均计时 0、无反击牌。第一轮队 0 压力归 0、计时置 4，不伤害。第二轮队 1 压力归 0、计时置 1，向队 0 请求 300 HP／20 压力伤害，队 0 变 HP −100、压力 20。

此时先计算崩坏，原层级 `[0,0]` 变 `[3,0]`，队 0 标志变 true；再判队 1 胜。没有 TurnStart，故该新标志仍 true、再考额度没有因它恢复，计时分别仍是 4、1。这与第一轮终局跳过崩坏不同。

### 9.3 连击攻击方不能替换普通攻击方

队 0 小心满怒，容量 4，手牌 `[0,1,2,3,-1,-1,-1]`，有效攻击 100，两项抖动均 0；队 1 HP 1000、压力 0。当前槽扫描先打代码 1，压紧后再打原代码 3，不打留下的代码 2；请求 HP 伤害共 300，压力共 6+13，队 1 变 HP 700、压力 19。队 0 留下 `[0,2,-1,-1,-1,-1,-1]`，连击结束记录攻击方 0、计数 2。

但补充元数据的普通 `attacker = 1`，队 1 原 `playedCard = 8`。非终局 TurnEnd 仍把先手改为 1、话题改为 2，不因连击攻击方为 0 而变更。队 0 计时 1→0，若其当前牌堆接着给 4、5，最终手牌为 `[0,2,4,5,-1,-1,-1]`、游标增加 2。队 1 因新崩坏恢复再考，标志随后清 false，但层级保留 1。

### 9.4 反击移牌产生的空位才是真正补牌需求

队 0 莽撞满怒；队 1 冷静满怒，容量 4，手牌为 `[0,13,2,3,9,14,-1]`。第一轮队 1 用镇静压制队 0：队 0 压力变 50，不进入莽撞；队 1 移除槽 1 镇静，压紧为 `[0,2,3,-1,-1,-1,-1]`，原非活动尾牌 9、14 已被移牌清除。第二轮队 1 自己进入冷静，计时置 4。

非终局衔接把计时降到 3并恢复队 1 再考额度；若牌堆下一项为 9，则补这一格，最终 `[0,2,3,9,-1,-1,-1]`，游标增加 1。若该队游标原为 18，则真正需要下一项时整笔拒绝，不能因愤怒前活动手牌已满而误报成功。

### 9.5 HP／压力、层级与补牌字段必须共同保留

双方小心满怒、各持容量 4 的 `[0,1,2,3,-1,-1,-1]`，初始 HP 均 1000，两队攻击值分别为 100、70，四项抖动皆 0。第一轮队 0 造成 300 伤害；第二轮队 1 造成 70+140=210 伤害、4+9=13 压力，且其进入愤怒先把自身压力清零。愤怒最终双方 HP 为 790、700，压力为 13、0，崩坏层级为 0、1。

衔接后两队计时 1→0，双方各补两张牌；队 1 因崩坏恢复再考。最终仍必须保留上述 HP、压力及层级，而不是拿仅含手牌／计时的回合衔接输出覆盖掉它们。最终连击记录属于第二轮队 1、计数 2；不能保留第一轮攻击方 0，也不能把两轮计数错误相加成 4。

### 9.6 计时和当前 18 牌边界

无新愤怒、无新崩坏、原再考皆 false 时，冷静计时 `[1,2]` 经 TurnEnd 变 `[0,1]`，TurnStart 额度应分别为 `[false,true]`。刚胆计时 2、活动手牌已经全满为 `[0,10,11,12]` 时，先降到 1，补牌没有新槽也不修补，最终零话题牌再清为 0。

当前游标 15、三个实际空槽，可恰取索引 15、16、17 后成功停在 18；当前游标 18、没有实际空槽也可成功。只有实际还需下一项才拒绝，因此“游标 18 一律拒绝”与“初始满手一律不需补牌”均不正确。

### 9.7 四项抽样跨阶段串联，不改局部编号

队 0 小心满怒、攻击 100、容量 4，活动手牌 `[0,1,10,11]`；队 1 压力 0、HP 1000，活动手牌 `[0,10,11,-1]`。一项抖动 0 使队 0 仅打出话题牌 1，队 1 变 HP 900、压力 6。原普通攻击方为 0，原已出牌为 `[11,1]`，有一次未被无视阻挡的诡辩话题抽样 2。双方当前牌堆随后都补入话术 10，队 0 修补值 0、队 1 修补值 8。

最终两队活动手牌分别为 `[0,1,10,11]`、`[0,9,10,11]`，各游标增加 1，话题为 2。外层四项顺序为连击抖动、话题重抽、队 0 修补、队 1 修补，编号为 0、1、2、3；两队各自补牌收据的局部抽样编号仍各为 0。若原话题也为 2，重抽仍保留一项消费，不能按“话题没有变化”把事件删除。
