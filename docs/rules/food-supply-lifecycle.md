# 耗粮与手动补给：独立资源会话规则

适用版本：PR #69 的 `detached-food-supply-v1` 与 `detached-food-supply-nearest-half-up-v1`。本页补充可调用服务实际采用的游戏资源规则；原作证据见[耗粮](20-food-consumption.md)、[补给](21-supply-transport.md)、[重叠与饥饿边界](47-food-overlap-starvation-exactness.md)。完整接口、JSON 与存档合同见[工程文档](../engine/food-supply-lifecycle.md)。工程政策不等于已恢复的原生事务。

## 1. 账户、容量与覆盖

账户分类为 combat、transport、city、port、gate，仅决定资源算术，不创建原生部队或据点。transport 的兵/金/粮容量为60000/100000/500000；combat 的金/粮为10000/50000，兵容量由调用方明确提供且不超过60000。city/port/gate 的容量明确提供。combat 的60000是服务支持域，不是所有原生主将的指挥上限。

combat 兵装1–4（枪、戟、弩、马）的对应库存等于兵数，装备容量至少等于兵容量；剑不要求每兵一件，攻具/船不按每兵消耗一件。其余兵装可作为惰性库存，不自动解释为真实运输任务。

每旬每账户必须有完整消费上下文。combat 的阵/砦/城塞候选同属且只能显式选一个，不叠加、不自动选最强；transport 校验但不使用覆盖倍率，驻屯账户不接受覆盖候选。政治为0–100；驻屯无太守时以政治0解释。覆盖胜者的原生选择规则仍未恢复。

## 2. 每旬耗粮的固定顺序

1. 先完整校验全部账户、上下文和本次旬序，不能部分扣粮后才发现另一账户非法
2. 旬初粮为0，跳过需求计算，实扣为0，不重复产生粮尽事件；需求/缺口记为未评估，而不是猜测为0
3. 港/关具有屯田时整个分支免粮，包括火灾额外耗粮；城市不适用该免除
4. combat 正常需求为 `兵数 × 覆盖倍率 × scale`；transport 为 `兵数 × scale`；驻屯为 `兵数 / 40`
5. 着火额外需求为 `旬初粮 × (600 − 5 × 政治) / 10000`；未着火为0
6. 正常与着火需求相加后仅向零截断一次；兵数大于0且结果小于1时取1
7. 实扣为 `min(旬初粮, 请求需求)`；缺口为请求需求减实扣

覆盖倍率按原float32位型解码：无覆盖 `0x40000000`，阵 `0x3FD55555`，砦 `0x3FAAAAAB`，城塞 `0x3F800000`；scale 为 `0x3D4CCCCD`。服务以精确有理数解释位型，不换成5/3、4/3或逐步fround。18000兵的阵覆盖请求为1499，不是1500。驻屯1/40和火灾十进制式采用精确有理数兼容解释，不宣称已恢复这些项的原bytes或完整x87中间精度。

正粮恰好扣完属于正常消费且产生本次粮尽标记；只有需求超过库存才属于不足。零兵未火需求为0，但零兵账户仍可因火损失存粮。消费只改粮，兵、金、气力、兵装不变。粮不足只报告，不掉兵；补粮后当前可用状态立即恢复为正粮，不沿用历史缺粮标记。

## 3. 手动补给的实际转移

只支持不同账户、同属的 transport → combat。相邻关系必须由调用方明确提供且两端ID匹配；服务不计算地图距离、不执行移动到达。请求必须分别写明兵、金、粮，不能省略为“最大”。

各资源接受量独立为 `min(请求量, 目标剩余容量, 来源库存)`。目标兵装1–4还以来源对应兵装库存限制接受兵数，并同时转移等量匹配兵装。所有量从命令开始快照计算后原子提交。未接受的请求不是已经扣出的库存：来源只扣接受量，不丢弃、不额外返还。逐账户逐资源核实非负、容量及守恒；消费的粮另记消耗汇。

接受兵数大于0时，令 `N = 旧目标兵 × 旧目标气力 + 接受兵 × 来源气力`，`D = 旧目标兵 + 接受兵`：

- `detached-food-supply-v1`：气力为 `floor(N/D)`
- `detached-food-supply-nearest-half-up-v1`：气力为 `floor((2N+D)/(2D))`

两者是版本化兼容政策，非原生非整除helper的认证。接受兵数为0则目标气力不变，不执行加权；来源气力始终不变。旧目标1兵/0气力加入1兵/1气力，两政策分别得到0和1。气力不是守恒资源。

## 4. 零兵、事务与边界

零兵保留同一账户及剩余库存、历史气力；可以转出最后一兵，在0兵时转金粮，或向0兵目标补兵。这不表示部队死亡、复活、创建或无人运输队行动。成功的零需求/零转移也记录一次命令；失败不扣资源或留下部分提交。重复成功命令ID拒绝，预览不提交；完整政策在会话内固定，保存/重放不得把一种气力政策静默换成另一种。

不产生经验、功绩或AP，不实现自动补给、饥饿损兵（包括0.76）、原生出征/归还/任务终结、捕获/归属/死亡/势力灭亡。P078及依赖继续排除。账户会话不是运输任务终点，不能把成功资源收据转换成原生finalizer许可。
