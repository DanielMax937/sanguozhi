## 恢复的三个helper

- `0070A330..0070A363`：两个64位操作数乘法，返回EDX:EAX低64位；高32位均0时走单次MUL快捷路，否则计算低项与两交叉项。这里不将它误称任意精度乘法。
- `0070A280..0070A329`：记录两个操作数的符号，对负值取绝对值，执行无符号双字除法/长除法，最后恢复异号结果；商向零截断，不是负数向下取整。除零不属于安全调用域。
- `005CA5B0..005CA5E2`：以有符号高dword、无符号低dword比较两个64位界限和中间值，返回夹在界限内的64位值。此调用传入INT32_MIN和INT32_MAX；不是城市库存容量裁剪。

005CA620先通过设施/城市/人物等门，然后取得politics低AL字节及city+0x7C原始价格。输入正粮数走买、负粮数走卖；返回的是有符号报价，不是本API承诺的世界金钱delta。正数表示买方报价，负数表示卖方报价；实际执行者如何更新库存仍不在本API。

## API与工程支持域

`calculateMerchantRawQuote(input)` 接受恰四字段普通有界数据：

```ts
{ profile: 'merchant-raw-quote-s1-resolved-v1',
  politicsByte: 0..255,
  rawTradePriceByte: 1..255,
  signedFoodQuantity: -2147483647..2147483647 }
```

所有数均为安全整数、禁负零。沿用`detachBoundedCityData`拒绝代理/getter/非数据原型/额外字段及超预算输入；不修改调用方对象。Node运行环境限制沿用该现有数据边界。

这是**已解析输入**：调用方负责给出真实getter结果，API不解引用地址、不验证原人物/设施资格、不执行价格更新。政治byte不等于旧服务pricePolitics，原指针无效时是否返回0也不能由本API错误结果代替。

price=0明确返回`zero-price-outside-domain`，不模拟CPU除零；INT32_MIN数量明确拒绝，避免把32位NEG溢出后的原控制流误当普通绝对值。它们是工程域限制，不声称原生UI会提交这些值。输入全部先校验，因此零数量配非法price仍拒绝；在本支持域零数量返回0并标记原函数早退，不实际使用三个helper。

## 已支持域的精确算术

设Q为粮量绝对值、p为politicsByte、r为rawTradePriceByte：

- 买：分子`Q*(450-p)*10`，分母`r*400`。
- 卖：分子`-Q*3200`，分母`(450-p)*r`。
- 分子/分母向零截断，最后夹到`[-2147483648,2147483647]`。

这是固定source profile内的推导；不是经验UI关系式的新证明。p域使450-p为195..450，r域使分母严格正。Q≤2147483647时最大买分子9,663,676,411,500，最大卖分子绝对值6,871,947,670,400，均小于2^44，更小于signed64上界；各中间乘积都不溢出。因此本**窄域**可用BigInt精确乘法实现该低64位helper，而不需要对未支持域伪造任意精度等价。

结果保留原输入、方向、带符号十进制分子/分母/截断前商/余数、int32夹值标记和来源等级。返回对象及共享evidence冻结，`stateWritten=false`。不创建新的可支出余额或价格缓存。
