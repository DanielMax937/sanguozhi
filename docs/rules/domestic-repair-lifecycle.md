# 已完成内政设施自动修复独立生命周期

2026-10-17，O11-B。`completed-domestic-auto-repair-v1` 为固定单城的标准内政设施提供独立正HP账本：从太守政治、工兵技法和每旬敌军位置自行计算资格与恢复请求，再执行上限裁剪、HP更新、到满事件及完整保存重放。只有 `AdvanceRepairTurn`，不接受调用方预先算好的恢复量。

[API与完整数据形状](../engine/domestic-repair-lifecycle.md) · [固定来源及证据分层](../sources/domestic-repair-lifecycle.json) · [结构schema](../sources/domestic-repair-lifecycle.schema.json)

本批是静态代码和规则覆盖，没有运行测试、typecheck、编译、build、checker、诊断、产品或示例；历史验证数字不适用于本树。公开listing数值重建、注释派生敌情政策及独立服务writer分别标注，不认证clean-stock PC-PK1.1、Vanilla或主机版。O11-A建设/吸收与O11-B维修是分离服务；不代表整个O11或原43组未决主题完成。

## 2. 输入域：固定归属与原始HP

场景必须显式供应：

1. 单个母城 `city`：`kind="city"`、稳定ID、固定 `ownerForceId` 和轴坐标。设施的 `cityId` 必须指向它；缺失母城或错误关联是无效输入，不作为可维修的“无城”情形继续执行
2. `governor` 为 `null` 或 `{id,politics}`；政治为0..255整数，表示已解析且本场景内固定的有效政治。`null` 合法，但所有设施跳过恢复。服务不自行选择太守、读取属性getter或解释原生身份
3. `engineering` 为固定布尔值，表示该母城所属势力是否拥有工兵育成（技法ID24）。不是从设施附近其他势力或任意据点取值
4. 最多30座设施：ID、母城ID、标准 `kind/level`、固定 `phase`、坐标、`currentHP/maxHP`。二者满足 `1 <= currentHP <= maxHP <= 32767`；不接受0HP、负HP、破坏态或复活
5. `hostileForceIds` 为固定敌对势力ID集合，最多128个；`completeFieldUnits=true`。每一个允许推进的旬边界都必须供应完整 `turnInputs[i].fieldUnits`，每旬最多128个单位。非敌对势力不造成阻挡
6. 日期年1..9999、月1..12、日仅1/11/21；有限 `1 <= advanceLimit <= 360`，完整逐旬输入长度与期限匹配，不能跨过日期支持上界；`turn` 非负且 `turn+advanceLimit` 必须仍为安全整数

坐标均为整数，范围 `-1000000..1000000`，采用axial `(q,r)`。设施ID及设施坐标各自唯一，设施不能与母城同格；每旬单位ID唯一，但不禁止多个单位共享坐标；敌对势力ID唯一且不能包含声明的母城owner。这里验证供应数据的内部约束，不校验原游戏真实归属。原始输入不接收 `baseRecovery`、`finalRecovery`、`writerReturn` 等答案字段。

### 2.2 固定phase与支持边界

- `complete`：只有受损且其余资格成立时恢复
- `building`、`absorbing`：跳过恢复，原HP保持；本服务不会完成施工、改变phase或推进建设work
- 已满HP：跳过，不重复发送 `hp-full`
- 不引入生产reservation语义。不能因另一模块的设施生产占用，擅自判断已完成设施无法自动修复

phase仅作供应的修复资格标记；任意支持kind/level均可搭配三种phase。这不证明相应的absorbing组合可由建设服务产生，也不认证施工状态的可达性。

`phase`、政治、工兵与母城/owner在本场景内固定，每旬单位集合、阵营与位置可通过已供应的完整tape变化；敌对势力ID集合固定。需要换太守、变技法、改变phase或受到新伤害，必须另有明确的外部组合/导入合同；本服务没有这些命令。

## 3. 从源listing推导请求值

在通过资格门槛后，令 `P=governor.politics`：

```text
nineP = 9 × P
half = floor(nineP / 2)
B = min(450, max(150, half))

engineering=false: request = floor(3 × B / 20)
engineering=true:  request = floor(3 × B / 10)
```

源地址及证据：

| 步骤 | listing范围 | 可支持的结论 |
|---|---|---|
| 政治读取 | `00599848..0059984D`、`0059989A..0059989F` | getter返回AL被零扩展，稳定已解析输入域是uint8 |
| 9P与半除 | `00599850..00599856`、`005998A2..005998A8` | LEA构成9P；CDQ/SUB/SAR1在非负域得到floor(9P/2) |
| 下上限 | `00599858..0059987F`、`005998AA..005998CF` | 夹到150..450 |
| 有工兵 | `00599864..00599870`、`00599884..00599890` | 先形成6B，再magic signed divide20，等于floor(3B/10) |
| 无工兵 | `005998B6..005998C0`、`005998D4..005998DE` | 先形成3B，再同一除20，等于floor(3B/20) |
| 符号校正 | `0059999F..005999A4` | `EDX + (EDX >>> 31)`；此非负小整数域不改变floor结论 |

`0x66666667` 高半积与移位是列表里的整数除法序列。本域所有数值都处于小正整数范围，不需要浮点常量、无界溢出猜测或从调用方接受最终恢复结果。

## 4. 资格与设施中心敌情

源 `00599720..00599738` 解析并检验设施；`0059973E..00599743` 检查已完成；`00599749..0059975C` 检查未满HP；`00599762..0059976F` 调用敌军helper；`00599775..00599787` 只分派固定据点/内政类型。内政母城、势力与太守检查分别见 `0059978D..005997DD`、`005997E3..005997ED`、`005997F3..00599812`。

服务不恢复原地图查城、native有效性或势力解析。其固定母城和目录验证是显式工程输入合同；无太守是独立合法跳过情形。

敌军helper `004B99B0` 的内部没有恢复。源注释写“城市3格，港关设施2格”，因此本域注册的是 `source-comment-derived-distance-policy`：从每旬完整供应的单位列表，找敌对单位到当前设施中心的距离

```text
dq = unit.q - facility.q
dr = unit.r - facility.r
distance = max(abs(dq), abs(dr), abs(dq + dr))
blocked = any hostile unit with distance <= 2
```

只保留最近敌军witness；距离并列时按单位ASCII ID排序选择。没有敌军时最近ID/距离为空。完整单位列表仍保留在输入tape及当旬快照，保存重放必须从原始位置重新计算witness，不能信任保存的blocked答案。

这里的中心是每座设施，不是母城。建设/吸收O11-A是“城市中心两格、阻止开始”的另一条政策；维修是“设施中心两格、阻止该设施本旬恢复”。不能仅因都出现数字2就复用建设gate，也不宣称本axial规则完整等价于未恢复的helper。

## 5. 逐旬状态转换和独立writer

创建场景仅建立genesis，不恢复HP。初始 `snapshot.fieldUnits=null`；第一次 `AdvanceRepairTurn` 取 `turnInputs[0]`，以后每次顺序消费一个完整旬快照。

每次合法推进：

1. 验证剩余期限和完整输入，推进一个1→11→21→次月1的边界；12月21日后进下一年1月1日
2. 设施按ASCII ID排序处理；从原始phase、HP、固定太守及当旬位置重新判断资格
3. 合资格设施逐项计算P、9P、半除、clamp、分子/分母与request，记录算术回执
4. 使用唯一注册的固定cap writer：`actual=min(request,maxHP-currentHP)`；`discarded=request-actual`；`currentHP += actual`
5. 仅当本次写入由低于上限首次达到 `maxHP`，记录本服务的 `hp-full` 事件；不调用原生完成、外观、消息或归属链

例如P=100、无工兵、HP499/500时，纸面请求67，实际1，弃置66，HP变500并产生一次本域到满事件；后续推进保持500且不再产生该事件。此例是公式推导，没有执行产品或示例。

回执记录请求/实际/弃置与HP前后值。cap是本服务完整、可重算的writer合同，不声称已恢复 `004AE360` 的完整实现或返回语义。v1不注册替代writer；不能只改policy ID、标志或保存中的policy对象就切到另一种writer。

本自动维修域不扣AP、金，不发TP、功绩、XP，也没有人员预留/行动标记。这是独立自动维修服务的无副作用合同，不从军事设施主动修补命令借入费用或奖励规则。

跳过原因的固定优先次序为 `not-complete → already-full → hostile-nearby → no-governor → repaired`。所有设施均计算敌军witness并输出一条回执；只有 `repaired` 有非空算术对象，其余记录0请求/0实际写入。

## 6. 命令、原子性、预览与持久化

- 命令只有 `AdvanceRepairTurn`，以唯一命令ID、`expectedRevision`及命令构成envelope；相同完整envelope重试为幂等，不能再次推进或重复写HP；同ID不同内容拒绝。重复请求返回原receipt及其中原events，但 `committed=false`；服务不派发外部事件，消费者应只在 `committed=true` 时消费事件
- 创建、执行、预览、保存、加载和重放都以固定profile、完整policy、目录与genesis为权威；历史每条命令、算术、gate、writer与最终快照必须重算匹配
- `preview` 在独立副本上得到同一推进结果，不修改调用方的账本；拒绝不产生半旬写入
- 缺失/错配母城、非法owner ID或自方列为敌军、非法kind/level、HP越域、未知字段、坏日期、缺旬、超期、输入预算超限或篡改的派生字段均不能变成部分成功；这些输入约束不验证原游戏真实归属
- JSON解析拒绝重复键；限制字节、节点、深度、数组长度、对象键数及历史/trace规模；不能以哈希相符代替完整重建。具体预算和错误形状以[API](../engine/domestic-repair-lifecycle.md)及固定policy为准
- 保存中的源profile、policy或catalog必须是完整固定内容，不能只检查版本标签。修改一条witness、算术回执、事件、HP或历史后，即使自行重算所声明的policy/catalog digest，也不能绕过genesis重建

这些是代码与schema声明的合同，本批没有运行验证。结构schema不能单独证明跨字段不等式、目录关联、数组唯一性、恢复算术或重放正确性。

## 7. 明确不覆盖的部分

### 7.1 城市、港、关

`00599943` 和 `00599971` 在同一地址各列两条互不兼容的指令：`6B C0 08 / IMUL EAX,EAX,8` 与 `8D 04 C0 / LEA EAX,[EAX+EAX*8]`。它们分别导出4P与4.5P基础量，不能拼成同一条原版字节流。无工兵额外0.4支路虽可局部辨认，却不消除这项身份冲突，也不证明最终整数比例精确2.5。城市/港/关不加入本服务。

### 7.2 堤坝、MOD及native尾部

堤坝 `005999F9` 以后走特殊未完成状态、最大耐久1/10和状态切换，不能以普通内政门槛覆盖；它还与旧FAQ“无太守不恢复”的概括有边界冲突。本服务排除堤坝。后附 `008A9A78` 筑城MOD也排除。

没有恢复 `004AE360` 耐久writer、`005899C0/00589980/0059FDD0` 完成与通知、`0057E5D0` 界面尾调用、原生对象查找/归属、全局旬调度或真实存档。P078/P0-78及关联capture、ownership、extinction、native mission/return/cancel/finalizer链不接入。

### 7.3 独立账本的组合边界

本HP账本不自动连接O11-A建设work，也不自动导入升级后的HP、生产reservation、战斗伤害、财政或EndTurn。将“先完工再修复”或相反作为全局顺序，都需要未来明确组合政策，不能默认来自本listing。

因此本批可准确描述为“已完成标准内政设施的公开listing数值与独立维修账本静态覆盖”。PK特殊楼、城市/港/关、堤坝、原版身份、native helper/writer/完成副作用和全局组合仍开放；原43组未决证据主题不减。
