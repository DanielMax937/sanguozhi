更新：2026-09-30。主目标版本：PC-PK1.1。补丁/版本差异留 E8 单独处理。

## 1. 系统结构

无印已有8系：

1. 枪兵
2. 戟兵
3. 弩兵
4. 骑兵
5. 练兵
6. 发明
7. 防卫


结构化数据见 `docs/sources/techniques.json`。

## 2. 研究成本与研究人员

每一系第1～4级费用固定：

| 等级 | 技巧P | 金 |
|---:|---:|---:|
| 1 | 1000 | 1000 |
| 2 | 2000 | 2000 |
| 3 | 3000 | 5000 |
| 4 | 5000 | 10000 |

研究：

- 最多/固定选择3名执行武将；
- 消耗50行动力；
- 必须先完成同系前一级；
- 特技“指导”使研究金钱减半；
- 技巧点本身上限为10000。

PC地址：

```text
00481A97 / 00481A9C
004B64B8 / 004B64BF
技巧P上限 = 10000
```

研究完成后参与武将获得的对应能力经验与本次消耗技巧P相关：

```text
能力经验 = 消耗技巧P / 100
```

所以4级分别为：

```text
+10 / +20 / +30 / +50
```

对应能力：

| 系 | 研究经验对应能力 |
|---|---|
| 枪 / 戟 / 弩 / 骑 | 统率 |
| 练兵 | 武力 |
| 发明 | 智力 |
| 防卫 | 政治 |
| 火攻 | 智力 |
| 内政 | 政治 |

E12 已对“研究完成功绩”做专项核对，完整证据见 `27-technique-research-merit.md`。

现有资料存在两套表：

```text

Lv4 +3000

2006早期攻略 / 同站小ネタ：

```

所以目前只可无冲突锁定 Lv1=500、Lv2=1000。Lv3/Lv4 的 PC-PK1.1 exact 常量仍未恢复。

项目为兼容现有行为暂保留：

```text
[500, 1000, 2000, 3000]
```

但证据等级已降为 `documented-current-wiki-candidate`，并在结构化数据中显式记录 `meritExactness = unresolved` 与旧表冲突；不得再称“源码确认”或“主表高置信”。

旧表恰好等于技巧P成本的一半只是算术特征，没有 PC 指令证明“功绩=技巧P/2”。


当前高置信语义：

- 防守方必须是应射势力的弩兵 profile；
- 触发对象是箭类攻击，而不是所有远程伤害；
- 弩普通射击、骑射、弩战法（含火矢/贯矢/乱射）等可触发；
- 必须满足正常反击的射程与地形合法性；

## 13. 一个重要分层：面板强化与伤害强化不是同一件事

精锐枪/戟/弩/骑同时存在两层：

### 面板层 E3

```text
基础攻击 +10
基础防御 +10
移动 +6/+6/+6/+2
```

### 战斗伤害层

```text
锻炼：1.10
精锐：1.15
精锐覆盖锻炼
```

因此不能把精锐实现成：

```text
面板+10，然后伤害1.10×1.15
```

正确是：

```text
面板按+10重新算
伤害层只选1.15
```

攻城兵器/舰船的战法伤害也不自动继承枪/戟/弩/骑“锻炼/精锐”的1.10/1.15。

## 14. 技巧点数据层

技巧点：

```text
上限 = 10000
```

获得/扣除由各种动作独立调用势力技巧点增减函数，不应和“技巧研究成本表”混为一张表。

例如已确认：

- 训练：`floor(actualMoraleGain/2)+5`；
- 击破敌军：相关地址记录+25（地址资料常以“2倍参数50”表示）；
- 断盟：-50；
- 各种计略/开发/探索有各自分支。

E7只定义技巧系统与研究，不重新把全部技巧P获得事件重审一遍。
